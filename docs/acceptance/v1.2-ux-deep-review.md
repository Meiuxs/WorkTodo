# WorkTodo v1.2 UX 深度审查记录

## 审查结论

本轮重点修正了计划视图的信息优先级：周视图不再让无计划日期占据同等视觉空间，工作记录不再只是指标平铺，而是先给结论，再给进度和节奏证据，最后展开明细。

## 主要问题与处理

### 1. 侧栏菜单层级偏弱

问题：导航按钮字号与内容正文接近，触控区域偏小，分组标题和菜单项的层级不够清晰。

处理：

- 菜单按钮提升为 15px、700 字重。
- 最小高度提升到 44px，改善键盘和触控操作。
- 保留分组标题、当前页背景和左侧强调线作为位置反馈。

### 2. 周视图把“没有计划”当成内容展示

问题：无计划的日期卡片与有计划日期占据相同空间，用户需要扫描大量空白才能找到重点。

处理：

- 只渲染实际有计划的日期。
- 日期改为独立卡片，卡片头部显示日期、计划数量和“今天”标识。
- 全部为空时显示单一空状态和明确的下一步提示。
- 完成、取消、删除沿用任务列表统一规则。

### 3. 月历信息密度缺少提示

问题：日期格内任务数量不明显，用户难以快速判断哪些日期值得进入。

处理：

- 有计划日期增加数量徽标。
- 今天继续使用语义色和文本日期双重标识。
- 保持七列结构和 390px 键盘操作能力，避免为了密度破坏可访问性。

### 4. 工作记录缺少报告阅读顺序

问题：原有指标条是并列数字，用户需要自行推断结论。

处理：

- 增加“本段结论”摘要卡。
- 增加完成率进度条，并同时保留百分比文本。
- 增加“工作节奏”报表，展示计划并完成、新增任务、延期次数。
- 保留原始指标与已完成明细，兼顾快速浏览和深入回顾。

## 设计约束

- 延续清透网格、暖白表面、深墨绿文字和青绿色行动色。
- 不使用纯颜色表达状态；数量、文字和结构同时表达信息。
- 不引入第三方字体、图表库、网络请求或扩展权限。
- 响应式布局继续覆盖 390px 视口，动效遵循 reduced-motion 设置。

## 验证

- 单元测试：195 passed。
- 端到端测试：51 passed。
- 新增验收：周视图只展示有计划的日期卡片。
- 月历 390px 键盘操作与横向溢出测试继续通过。

## 工作记录卡片报表补充

- 工作记录采用“结论双卡 → 核心指标 → 工作节奏 → 完成明细”的阅读顺序。
- 结论区恢复轻量卡片表现，保留暖白表面、细边界和现有清透网格视觉语言。
- 指标继续完整展示，但不为每个数字增加独立阴影或大圆角，避免形成卡片堆。
- 任务明细保持线性列表，方便连续扫读和回顾。
- 无计划状态明确显示“暂无计划”，不再让辅助文本把它读成 0%。
- 工作记录 DOM 结构、总结生成、复制、异步切换和 390px 无横向溢出均有测试覆盖。
- 本次完整验证：198 个单元测试、54 个端到端测试全部通过。

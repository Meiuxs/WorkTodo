# 以任务闭环为核心并保持资料与提醒边界

WorkTodo 面向需要从记录一直推进到回顾的单人知识工作者，因此决定把产品核心定义为完整的任务闭环：收集箱只是待整理队列，资料是任务的可选上下文，任务使用单一主计划日期而不是同时引入计划日期与截止日期。我们暂不把提醒/通知纳入当前边界，以避免在离线浏览器扩展中引入额外权限和不可靠的时间触发；先确保完成、取消、撤销、恢复、延期和工作记录形成可信的闭环。

## Considered Options

- 把资料和提醒做成与任务同等的一等对象：暂不采用，会分散核心任务路径并扩大权限与交互复杂度。
- 同时引入计划日期和截止日期：暂不采用，等真实使用场景证明单一主计划日期不足后再拆分。

## Consequences

- 快捷日期和优先级操作应服务于任务行内推进，而不是把快速记录变成长表单。
- 误操作必须有分层恢复路径：撤销创建、状态恢复、回收站恢复和永久删除各自语义不同。
- 后续若加入提醒或独立截止日期，需要新增 ADR，并重新评估数据模型、权限和回顾语义。

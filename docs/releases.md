# 版本发布记录

`manifest.json` 的 `version` 是扩展发布版本的唯一来源，`package.json` 的版本号不作为扩展包版本依据。版本升级规则、发布步骤和命名约束见 [`AGENTS.md`](../AGENTS.md) 的「版本与 GitHub 发布」一节。

每个版本记录六项：版本号、变更摘要、测试结果、包文件名、GitHub Release 链接、tag 名称。包体积与 sha256 取自 GitHub Release 附件；回填时已核对本地 `dist/` 下的同名压缩包与附件逐字节一致。

## 回填说明

本文件在 `v1.5.2` 发布之后回填，`v1.5.3` 的条目在 `v1.6.0` 发布前一并补齐，因此部分字段只能记录可核实的事实：

- **测试结果**：`v1.5.3` 及更早版本发布时没有保存当次测试输出，为避免把事后结果记成发布时的结果，统一标记为「未留存」；`v1.5.2` 的数值是回填时在本机对同一提交复跑所得，`v1.6.0` 是发布当次的运行结果。如需补齐更早版本，可逐个检出对应 tag 后运行 `npm test`。
- **tag 类型**：`v1.4.0` 与 `v1.5.0` 发布时是轻量 tag，回填时改写为带注释 tag。两个 tag 指向的提交没有变化（`925a2df`、`d5a80a0`），因此对应 Release 和附件不受影响。`v1.2.0`、`v1.5.1`、`v1.5.2`、`v1.5.3`、`v1.6.0` 本来就是带注释 tag。
- **更早的版本**：`v1.1.0`–`v1.3.1` 早于发布流程规则，只有本地压缩包，没有 tag 与 GitHub Release。按「后续发布不得复用已有版本号、tag 或 Release」的约定，这些版本号不回补，也不重新发布。

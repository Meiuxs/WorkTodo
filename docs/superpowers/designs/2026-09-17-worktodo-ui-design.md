# WorkTodo v1.6 UX/UI 设计规范

> 状态：当前产品规范
> 更新：2026-09-24
> 适用范围：首次使用引导、Popup、Dashboard、任务列表、工作记录、资料收集箱、任务编辑抽屉、确认对话框、Toast、空/错/成功状态
> 关联实现：`src/styles/tokens.css`、`src/popup/`、`src/dashboard/`、`src/welcome/`

这份文档是 WorkTodo 的 UX/UI 共同约束。UX 决定用户先做什么、如何完成任务以及如何恢复；UI 决定这些路径如何被看见、操作和理解。新增页面或组件必须先回答对应的用户问题，再选择视觉组件。

## 1. 产品定位与设计目标

### 1.1 用户与场景

WorkTodo 面向在受限办公环境中使用 Chromium 的单人知识工作者，例如工程技术、项目、销售和行政人员。他们经常在会议、邮件或浏览资料的间隙想到一件事，需要用几秒记下，然后在合适的时间整理、推进和回顾。

### 1.2 核心问题

用户打开 WorkTodo 时通常只需要回答三个问题：

1. 现在最该推进什么？
2. 新想到的事情放在哪里最合适？
3. 我完成了什么，下一步还剩什么？

### 1.3 体验目标

- **三秒记录**：首次记录只需要标题和一次 Enter，不强迫用户立即分类、安排时间或填写描述。
- **一眼看清**：今日页优先呈现逾期、下一步和完成进度，低频内容后置。
- **逐步展开**：先完成最小动作，再通过抽屉、详情和报表逐步补充信息。
- **行动可恢复**：完成、延期、取消、删除和导入等动作都提供清楚反馈、撤销或恢复路径。
- **本地可信**：明确说明数据存储、保存失败、导入风险和恢复方式，不使用技术错误码吓阻用户。
- **离线可用**：核心记录、完成、延期、回顾和数据操作不依赖网络。

### 1.4 品牌与审美方向

WorkTodo 的审美是 **清透网格**：薄荷灰画布、暖白工作面、深墨绿文字、青绿色行动色、橙珊瑚色提醒。使用结构化网格、细边界和轻微层级差建立秩序，不使用霓虹渐变、玻璃拟态、发光装饰或装饰性卡片堆叠。

界面应该让工作有向前推进的感觉，但不制造紧张感；文案直接、短促、有行动指向。

## 2. UX 信息架构

### 2.1 页面职责

| 入口 | 用户问题 | 页面职责 | 不应该承担 |
| --- | --- | --- | --- |
| Popup | “我现在想到什么？” | 快速记录、显示少量今日重点、提供工作台入口 | 完整编辑、复杂筛选、长表单 |
| 今天 | “现在最该推进什么？” | 逾期、下一步、今日进度、快速记录 | 月度分析、资料管理 |
| 明天/本周/月历 | “接下来怎么安排？” | 计划日期、周节奏、月度分布 | 临时记录的复杂编辑 |
| 收集箱/全部任务 | “我有哪些事项？” | 找回、搜索、筛选和批量理解任务 | 用弹窗承载整页任务浏览 |
| 工作记录 | “我实际完成了什么？” | 周/日回顾、完成节奏、统计和明细 | 把总结编辑器作为首屏主内容 |
| 资料收集箱 | “上下文资料放在哪里？” | 保存、搜索、关联和下载资料 | 强迫用户在记录任务时填写资料 |
| 设置 | “数据如何保存和迁移？” | 主题、导入、导出、分类管理 | 把危险操作做成无确认的一键动作 |
| 首次使用引导 | “怎样开始用 WorkTodo？” | 用一分钟说明快速记录、补充分类、完成或改期，并提供今日工作台入口 | 代替工作台操作或要求用户完成教程 |

首次安装扩展时打开引导页一次；更新、重启扩展或后续启动都不重复打开。引导页提供通往今日工作台的主入口，用户可以直接关闭或稍后再看。设置页保留“重新查看使用说明”链接。主题沿用用户设置与系统偏好；文案说明任务保存在本机、可离线使用。

### 2.2 主路径

```text
想到事项 → Popup/今日页快速记录 → 今天
        → 需要安排时选择日期或打开任务抽屉
        → 今日页完成/延期/取消
        → Toast 告知结果并提供撤销
        → 工作记录按实际完成日期回看
```

每个页面只保留一个主要推进方向。页面上的次级动作可以存在，但不能和主动作使用同等视觉重量。

### 2.3 信息优先级

Dashboard 今日页固定采用以下顺序：

1. 页面标题和当前日期；
2. 快速记录入口；
3. 逾期事项；
4. 今日待推进事项；
5. 完成进度与已完成折叠区；
6. 低频管理或辅助信息。

工作记录固定采用以下顺序：

1. 本段结论；
2. 完成率和四项核心指标；
3. 工作节奏或今日回顾；
4. 规则模板总结（按需生成）；
5. 实际完成明细。

### 2.4 状态保存范围

工作台使用地址栏 hash 作为视图状态的唯一来源：

- 路由写在路径段（例如 `#week`、`#settings`），视图级参数（全部任务的筛选条件、工作记录的区间与锚点日期）写在查询段，由 `src/dashboard/hash.js` 统一读写。
- 刷新、前进/后退和收藏深链都能停在原视图与原筛选；导航离开再回来以 hash 为准。
- 视图内部切换筛选时只在路径未变化时更新查询段，不触发整页重路由。
- 如果将来引入多窗口共享状态或可分享链接，仍在 hash 体系内扩展，不引入服务端状态。

## 3. 视觉系统

### 3.1 颜色语义

颜色只表达稳定的产品语义，不用颜色替代文字和结构：

| 令牌 | 用途 | 语义 |
| --- | --- | --- |
| `--canvas` | 页面背景 | 环境层 |
| `--surface` | 普通内容面 | 内容层 |
| `--surface-raised` | 输入、浮层、主动卡片 | 抬高一层 |
| `--ink` | 标题、正文、主要操作文字 | 主要信息 |
| `--muted` | 辅助说明、时间、低频信息 | 次要信息 |
| `--line` / `--line-strong` | 分隔线、控件边界 | 结构和可操作边界 |
| `--teal` / `--teal-soft` | 主行动、完成、正向进度 | 可以推进 |
| `--coral` / `--coral-soft` | 逾期、删除风险、需要注意 | 需要确认 |
| `--overlay` | Dialog/抽屉背景遮罩 | 当前焦点在浮层 |

浅色和深色令牌统一维护在 `src/styles/tokens.css`。业务样式不得重新定义相同语义的颜色，也不得直接使用纯黑或纯白作为大面积背景。

### 3.2 排版层级

- 字体使用系统中文字体栈，不加载远程字体和 CDN。
- 正文使用 `14px`；界面辅助文字使用 `12–13px`；Popup 标题使用当前 `24px` 主题级标题，Dashboard 主标题使用 `30px` 主题级标题。
- 标题使用清楚的字号差异和 `text-wrap: balance`；正文使用 `text-wrap: pretty`，避免中文孤字。
- 数量、日期和时间使用 `font-variant-numeric: tabular-nums`，减少数据变化造成的跳动。
- 省略号使用中文排版的 `…`，加载文案统一使用“正在加载…”，不使用三个句点。
- 文案不重复解释已经在标题中表达的信息；按钮名称要描述动作，例如“保存任务”“移入回收站”，不使用单独的“继续”“确定”作为主要动作。
- 界面文案只对用户说话：不写实现细节、模块依赖或“与某页规则一致”这类内部约定。需要解释产品规则时，写进本文档或 README，不要占用页面说明行。
- 被单行截断的文本必须能取回全文：允许展示两行，或提供 `title` 属性、详情入口；不得让用户在界面上永远看不到完整标题。

### 3.3 间距、尺寸与层级

- 基础间距以 `4px` 为刻度，优先使用 `8 / 12 / 16 / 20 / 24 / 32px`。
- 普通输入和按钮使用统一控件高度；Popup 主输入使用更高一级的控件高度，确保首屏主入口明显。
- 圆角只用于表达控件或浮层边界：输入和按钮使用小圆角，面板使用中等圆角，不把每一行都包成卡片。
- 分区面板只用于「多项互不相关的设置并列」的页面（目前是设置页）：容器用 `--surface-raised` 底色 + 1px `--line` 边界 + `--shadow-card` 的抬起暗示，一个分区一块，不在面板内部再拆子卡片，也不逐行拆卡。
- 完整投影（`--shadow-float`）只用于抽屉、Popup 浮层、菜单和 Toast；其余内容优先使用留白和 1px 边线。
- 线的数量由相邻关系决定，不由组件个数决定：**同一处相邻关系只保留一条边线**。区块之间优先用留白和标题层级分层，不再额外画顶线；容器已有边界时，其内部的首行顶线与末行底线由容器边界承担，不再重复绘制。判定方法：把一条线拿掉之后两块内容仍然分得开，它就是重复线。
- 上述减法只针对装饰性的重复线；竖线、真容器边界（分区面板、卡片、抽屉、对话框、危险区域）、真实数据网格（月历格、周卡片）以及页面级空状态的收尾下边线不在减法范围内。空状态那条线是全产品统一的段落终点标记，各页面要么都有、要么都没有，不得单页关掉。
- 主内容列保持可读宽度并左对齐，不为了“居中好看”牺牲连续阅读。

## 4. 核心组件规范

### 4.1 Popup：三秒记录

Popup 目标宽度为 `360–380px`，高度随内容变化。结构固定为：

```text
今日日期                         ↗ 工作台
记下下一件事
快速记录 · 只写标题，稍后再整理
完成进度
逾期/今天要推进
标题输入框                         ＋
[今天] [明天] [收集箱]
成功反馈（需要时出现在内容流中）
```

交互规则：

- 打开后焦点进入标题输入框；这是 Popup 中唯一默认自动聚焦的主输入。
- 只输入标题即可保存；默认安排到今天，日期按钮可切换到明天或收集箱。与 Dashboard 今日页快速记录保持一致，让临时想到且准备推进的事项直接进入今日主线；确实未决定日期时再主动选收集箱。
- 宽度用固定像素，不使用 `vw` 等视口单位：扩展弹窗的窗口尺寸由文档宽度倒推，视口单位又按弹窗视口解析，两者互相依赖——Chromium 会退到最小内容宽度，弹窗塌成一条竖条、每行只放得下几个字。只有真实弹窗里才会暴露，普通标签页打开 `popup.html` 测不出来。
- Popup 最多显示少量重点任务，超过范围通过“打开工作台”处理：逾期与今日两个节各自取配额，逾期不得挤空今日节；两节都为空时才能出现空状态。
- Popup 完成父任务同样级联完成活动子任务：两端不得因入口不同而产生不同数据结果；Popup 不弹确认，靠级联数写入 Toast 与撤销覆盖父与子兜底。
- “打开工作台”是文字型次级入口，不和“添加任务”争夺主行动层级。
- 成功 Toast 必须位于内容流中或有明确安全偏移，不能覆盖日期按钮、输入框或提交按钮。
- 成功反馈至少说明“发生了什么”和“下一步可以做什么”；需要撤销时显示可操作的“撤销”按钮。

### 4.2 Dashboard 快速记录

- 输入框是执行和整理页面的稳定主入口，标题是唯一必填字段；在已完成、回收站、工作记录、资料收集箱和设置等回顾或管理页面隐藏，避免新增任务的去向与当前页面语义冲突。
- 入口随路由提供安全默认去向：今天默认“安排今天”，明天默认“安排明天”，收集箱和全部任务默认“先放收集箱”；本周与月历同样默认收集箱，不能猜测用户要安排到该范围内的哪一天。
- 计划日期、更多字段和资料关联采用渐进披露，不把完整表单塞进首屏。
- 提交按钮保持可见且使用主行动色；提交期间反馈状态，失败时保留原输入并给出下一步。
- 操作顺序固定为「输入标题 → 选择计划日期 → 补充详情 → 记录」，与用户“先写、再归属、再保存”的心智一致；主提交按钮必须位于行尾，不得插在输入框与日期选择之间。
- 快速记录的日期校验必须就近反馈：指定日期为空时，录入区取消激活色，日期控件使用错误边框和 `aria-invalid`，错误文案紧贴日期控件并将焦点落到该控件；填写后立即清除错误态。
- 「补充详情」是次级图标按钮（`⋯`，可访问名保持“补充详情”），不使用主行动色，也不与「记录」争夺视觉焦点。
- 快速记录区域不得被 Toast、菜单或其他 sticky 元素覆盖；键盘焦点移动时也必须保持可见。

### 4.3 任务行

任务行是高频浏览单元，不是卡片集合。每行可以包含：

- 原生 checkbox 或等价键盘控件；
- 任务标题；
- 计划日期/时间或“无时间”；
- 优先级、逾期、延期等文字状态；
- 标签（任务名下方的元信息行，最多平铺两个，其余折叠为 `+N`）；
- 悬停或键盘聚焦后出现的次级操作。

元信息行的截断与标签规则：

- 元信息行由两块组成：可截断的文本段（状态 · 日期 · 优先级 · 子任务数 · 资料数）与标签块。宽度不足时只压缩文本段，标签块不参与整行截断——标签是任务行里唯一的归属线索，不能被日期和优先级挤掉。
- 标签最多平铺两个，其余折叠为 `+N`；完整清单写入 `title`，悬停和读屏都能拿到全部归属。
- 标签块自身超长时最多占半行并在内部截断，保证状态与日期始终可读。
- 标签前的分隔符由样式 `::before` 承担，标签文本内只保留标签本身，避免读屏念出孤立的间隔符。
- 密度视图（桌面月历格）不展示元信息行，因此也不展示标签；窄屏月历恢复元信息行时，标签块必须一并保留。
- 行首完成控件统一为圆角方形复选框（checkbox），不使用圆形：圆形在惯例上表示单选，会误读完成语义。已完成时显示勾选并保持控件可见。

状态必须同时使用文字、结构或控件状态表达：

| 状态 | 视觉 | 文字/行为 |
| --- | --- | --- |
| 待办 | 普通文字、空心控件 | 可完成、延期或打开详情 |
| 进行中 | 青绿色轻强调 | 显示“进行中” |
| 已完成 | 低对比度、完成时间 | 可恢复，不能只依赖删除线 |
| 已取消 | 灰化 | 显示“已取消” |
| 逾期 | 珊瑚色小范围强调 | 显示“逾期”和原计划日期 |

### 4.4 任务编辑抽屉

抽屉适合编辑任务，不适合快速记录：

- 从右侧进入，桌面宽度约 `420px`，窄屏使用可用全宽。
- 详情按「基本信息 → 整理 → 更多选项」分层：基本信息显示任务名称、计划日期、优先级和描述；整理区集中分类与标签；时间、重复任务、资料和子任务放入可折叠区。折叠行本身说明可展开的内容，不再增加重复的补充提示。
- 开始时间与截止时间默认收在「时间」折叠项内，并在摘要中展示当前设置；只有用户需要时才展开，避免与计划日期、优先级争夺首屏注意力。
- 星标是名称行右侧的 `☆` / `★` 开关，不单独占一行。它必须有随状态变化的可访问名，不能只靠字形表达“已标记”。
- 次级区一律以可展开入口行呈现：一行一个 `<details>`，`summary` 左侧是组名、右侧是**当前值或计数摘要**。摘要必须在用户改动后立即更新——收起不得把信息拿走。
- 折叠只用一套词汇（`.editor-group`），不再出现两种折叠外观；含 `<fieldset>` 的组把 `<legend>` 降为 `sr-only`，可见标题由 `summary` 承担。
- 默认全部收起，不记忆展开状态：每次打开表现一致。
- 分类在设置页创建和维护。任务详情的分类选择旁必须提供直达分类管理的链接，打开单独的工作台标签并定位到分类区，保留当前未完成的编辑；用户返回后聚焦分类选择器时重新读取分类，立即可选刚创建或改名的分类。
- 分类管理行的重命名与删除按钮共享固定尺寸、网格居中和一致的点击区域；危险语义由动作名称与悬停状态表达，不改变图标的对齐基线。
- 出现条件：新建任务时出现分类、标签、重复任务、更多信息；已有任务时出现分类、标签、资料、子任务、更多信息（资料需要 task id，重复规则只能在创建时设定）。
- 底部固定“取消”和“保存任务”，抽屉主体独立滚动，并使用 `overscroll-behavior: contain`。
- 打开后焦点进入任务名称；Esc 和取消关闭，焦点回到触发元素。任何把焦点或注意力移入收起区的路径，都必须先展开该组。
- 保存失败不关闭抽屉，不清空输入；并发冲突提供“保留为新任务”和“载入最新版本”，并让冲突面板进入视野、焦点落在“载入最新版本”。

- 头部标题只承担“我在改哪条任务”：最多两行，超长即截断，不在头部重复展示全文（全文就在名称输入框里）。不截断时，200 字的标题会把头部撑到 `260px` 以上，把整列入口行挤出首屏。
- 次级区内部的排布只有一套：字段名在输入框上方；“输入 + 主操作”行与抽屉内其他控件共用同一左边界；空提示排在主操作之前（说明在前、动作在后）。不得出现“标签在输入框左侧”和“标签在输入框上方”两种对齐在同一屏并存。
- 展开后的资料区顺序固定为：资料列表或空提示 → “添加资料”。主操作左对齐，不做右对齐，也不排在说明之上。

### 4.5 确认对话框

确认框只用于不可逆、风险较高或需要用户明确选择的动作：删除、永久删除、覆盖导入、完成仍有子任务的父任务等。可撤销的移出类动作（移入回收站、取消）不用确认框，直接执行并用加长撤销窗口的 Toast 兑付（见 §4.7）；同一动作不得“确认 + 撤销”双摩擦。

- 统一使用产品内 `dialog`，禁止新增浏览器原生 `window.confirm`。
- 标题直接说明风险，例如“删除资料？”“覆盖本机数据？”。
- 说明文字解释影响和恢复可能性；不显示技术错误码。
- 危险按钮使用明确动作名称，例如“删除资料”“确认覆盖并导入”，不使用“确认”。
- 默认焦点优先落在取消/安全动作；用户按 Esc 可以取消。
- 对话框宽度不超过视口，长内容在内部滚动，不能让背景页面跟随滚动。

### 4.6 资料表单对话框

- 用于添加资料、关联任务等短流程；每个字段有可点击标签或 `aria-label`。
- 根据资料类型只显示相关字段，避免让用户阅读无关表单。
- 失败信息贴近字段或表单底部，并保留用户已输入内容。
- 窄屏或内容过长时限制在视口内滚动；操作按钮和内容之间使用边线区分。
- 本地文件、网页链接、文本片段的说明必须告诉用户保存方式和大小边界。
- 资料收集箱和全部任务页面的标题只保留页面名称，不添加解释性副标题；筛选入口和页面结构直接表达能力，避免把开发说明写进界面。
- 资料为空时在页面级空状态提供唯一的“立即添加第一份资料”主入口，此时头部标题行不同时渲染“添加资料”，避免同屏出现两个指向同一动作的主按钮；列表非空后入口回到头部标题行。
- 资料列表的正文摘要最多显示三行，超出部分由省略号截断；点击正文摘要或标题打开资料表单查看全文。关联任务只保留“关联任务”动作，不重复显示“未关联任务”等状态文案。
- 已完成页为空时使用“勾选待办任务即可完成”的动作文案；空状态不额外绘制底边，只保留下方“已取消”折叠区的上边线。

### 4.7 Toast 与异步反馈

Toast 是非阻塞反馈，不代替页面状态，也不承担确认动作：

- 使用 `role="status"` 或等价的 `aria-live="polite"`，让读屏用户能收到结果。
- 文案先说结果，再说可选动作；例如“已移入回收站 · 撤销”。
- 默认显示约 5 秒，危险或需要用户处理的错误应留在相关字段或页面，而不是只闪过 Toast。
- 撤销窗口按“是否还有二次机会”分级：行仍留在当前视图的动作用约 5 秒；移入回收站、取消这类行立即离开视线的动作也用约 5 秒，且秒数必须写进 Toast 文案（例如“已移入回收站，5 秒内可撤销”），用户不需要猜窗口还有多久。
- Toast 不得遮挡输入、日期按钮、快速记录、底部菜单和当前焦点。
- 进入/退出只使用 `opacity` 和 `transform`；遵守 `prefers-reduced-motion`。

### 4.8 任务行“更多”菜单

次级操作只在需要时展开，避免任务行变成按钮集合：

- 触发器是原生 `<details>/<summary>`，`summary` 提供 `aria-label="更多任务操作：{任务标题}"`（可访问名必须含动作对象，同屏多行时不得出现同名按钮），Enter/Space 可展开。
- 触发器默认只呈现省略号图标 `⋯`（与「补充详情」同一套图标词汇），不再写“更多”两个字：图标占固定方块，宽屏上不与标题争夺同一行的注意力，也不需要跨语言文案。
- 有精确指针的设备上图标默认不显形，行悬停、键盘聚焦或菜单展开时才显现；触屏与窄屏必须常驻显示，不得以“默认隐藏”为由让移动端失去完成、延期或删除入口。
- 菜单保持扁平：不再在浮层内嵌套二级子菜单，整张菜单展开后不超过一屏、无需滚动。
- 菜单内按“常用 → 次要 → 危险”排序：开始/取消/星标、改期快捷档、编辑任务（子任务、标签、更多字段）、复制；移入回收站用分隔线孤立在底部，破坏性色只用于它和永久删除。
- 改期区块只保留换算好的快捷预设：今天、明天、下周；预设文字必须带具体日期，避免用户自己换算。自定义日期和移除计划日期不在菜单中出现，由编辑抽屉的计划日期字段承担。
- 优先级不进菜单：默认档位是“无”，四档平铺会挤爆菜单；在抽屉中编辑，行内快捷键 `P` 沿“无→低→中→高”循环作为高频用户的快捷调整，结果必须有 Toast 反馈。
- 任务行获得焦点时，`D` 展开菜单并聚焦改期区块首个按钮，`P` 直接循环优先级（不展开菜单），不与全局导航快捷键冲突。
- 菜单限高可滚并 `overscroll-behavior: contain`，仅作窄屏 bottom sheet 的兜底；窄屏、键盘和指针必须触达同一组动作；不得用 `display: none` 让某一端失去完成、延期或删除能力。
- 回收站行是例外：它的行内动作只有「永久删除」一个，因此不渲染「更多」菜单，直接把该动作作为行尾按钮呈现（`.task__danger`，尺寸与「更多」触发器一致，颜色用破坏性色）。恢复仍由行首方形复选框承担，不得为它再加第二个入口；永久删除的二次确认要求不因入口前移而改变。

### 4.9 侧栏数量角标与快捷键提示

- 角标只复用目标页面已有的数字（今天页逾期数、收集箱总数），不引入新的状态口径。
- 角标本身 `aria-hidden`，不参与按钮的可访问名称；数字通过按钮的 `aria-describedby` 交给读屏，例如“3 项逾期待处理”。
- 数量为 0 时角标隐藏，导航项名称与排序保持不变。
- 快捷键的完整清单放在设置页“键盘快捷键”参考表（导航 T/W/M、快速记录 N、搜索 F、任务行 D/P），含使用条件（输入框内不生效、弹窗打开时暂停）；入口上不再就地展示 `kbd` 徽标，避免侧栏和表单里散落零散提示。按钮仍用 `aria-keyshortcuts` 向读屏声明。
- 清单保持完整可达，不折叠进弹窗：宽屏按两列排布，`≤680px` 回落单列，避免七条平铺占掉大半屏设置页。两列只改视觉列数、不改语义——表格改用 `grid` 排布后浏览器不再给出隐式 table 角色，因此标记上补 `role="table"/"rowgroup"/"row"/"rowheader"/"cell"`，读屏与 `getByRole('cell')` 结果保持一致。

### 4.10 子任务的内联显示与父完成级联

子任务（仅一级，子任务不再套子任务）不单列成顶层行，而是内联嵌在父任务行下方：

- 显示位置：父 `<article class="task">` 内以 `<ul class="task__subtasks">` 跨整行、缩进到标题列；子任务行只保留一个可勾选方形复选框、标题（点开进入编辑抽屉）与状态文字，字号比顶层任务收敛一档以建立层级差。
- 归位规则：列表只渲染顶层任务；当某子任务的父任务也在同一集合内时，该子任务从顶层移除、只以嵌套形式出现，避免既平铺又重复。父任务不在当前视图（例如计划日期不同）时，子任务仍平铺保留，确保子任务永不消失。子任务多无计划日期，因此今天/本周/月历按日期筛选时只作为父行的嵌套项出现。
- 进度表达：父任务元信息追加“子任务 已完成数/总数”，用文字而非仅靠颜色表达进度。
- 勾选语义：子任务方形复选框为 `role="checkbox"`，可单独完成/恢复；完成子任务不触发级联，也不影响父任务状态。
- 父完成级联：完成父任务时若仍有未完成子任务，先弹确认（标题“完成父任务及其子任务？”、确认按钮“完成全部”）说明会同时把这些子任务标记为已完成；确认后级联完成活动子任务，再完成父任务。取消则两者都保持不变。撤销 Toast 逐个恢复父任务与被级联完成的子任务。
- 增量更新：子任务行用 `data-subtask-id` / `data-subtask-action`，不占用 `data-task-id`，以免破坏列表按顶层行对齐的 patch 协调；子任务动作后按 id 恢复该复选框焦点。

### 4.11 侧栏导航与设置入口

Dashboard 侧栏的导航结构固定为：无标签的「今天」主入口，加三组带标签的分组（计划、任务、回顾），最后是设置入口。

- 「今天」是唯一没有分组标签的条目，与品牌区之间额外空出一档间距；它是工作台的常驻主入口，不与「计划」组混排。
- 「计划」组含明天、本周、月历；「任务」组含收集箱、资料收集箱、全部任务、已完成、回收站；「回顾」组含工作记录。
- 设置入口不单独成组，也不吸底。它紧跟在「回顾」组之后：分隔线距上一条一个分组间距 `--sp-6`，按钮距分隔线 `--sp-4`。
- 层级差由结构和颜色承担，不由尺寸承担：分隔线用 `--line`，设置条目默认文字色 `--muted`，`:hover` 回到 `--ink`，当前页回到 `--teal`。它的 `min-height`（44px）与字号（`--fs-nav-item`）和普通条目完全一致。
- 设置入口位于 `<nav aria-label="工作台导航">` 地标内，读屏“跳转到导航”可以直达；它不得作为该地标的兄弟节点存在。
- 侧栏条目一律不使用图标。11 个条目里有四对近义项（明天/本周、收集箱/资料收集箱、全部任务/已完成、工作记录），图标无法唯一区分；且本产品不引入 SVG 资源与图标字体。将来若要引入整套图标语言，须作为独立决策，定义图标集、尺寸、线宽、深色主题处理和 `aria-hidden` 规则后再实施。
- 导航条目只有一套样式来源：`.nav button`。底部区不作为并列组件另写一份声明，它的差异只由 `.nav__footer` 这个结构表达。

### 4.12 设置页数据管理

数据管理区是设置页里唯一涉及数据风险的地方，动作集合固定为：导出 JSON 备份、导出 CSV、选择导入文件、清除所有数据。

- 清除所有数据不可逆，不得与「导出 JSON 备份」并列成排；它归入页面最下方的「危险区域」，与数据管理区完全分成两块（见 §4.13），不再只靠一条分隔线区分。
- 清除范围限定为业务数据：`tasks`、`categories`、`tags`、`events`、`recurringTemplates`、`searchIndex`、`resources`、`taskResources`、`resourceBlobs`，以及 `chrome.storage.local` 的 `metadata`。`settings`（主题等偏好）不在范围内，也不得被顺带重置。
- 清除必须走 §4.5 的确认对话框：标题「清除所有数据？」，说明同时交代清除范围、保留项和“无法恢复、不能撤销”，危险按钮具名为「清除所有数据」，默认焦点落在取消。
- 不强制先导出备份，只允许在确认框里给出“建议先导出 JSON 备份”的提示。
- 结果复用数据管理区的 `role="status"` 区域播报：成功为「已清除全部本地数据；主题等偏好设置已保留。」，失败为「清除没有完成，本机原有数据保持不变。」；失败时不得留下半清状态。
- 清除后焦点回到设置页里的「清除所有数据」按钮，不得因整页重渲染把焦点丢到 `body`。
- 不提供撤销，也不新增按时间范围、按列表的部分清除能力。

### 4.13 设置页分区面板与危险区域

设置页同时承载外观、数据管理、分类、快捷键四类互不相关的设置，用分区面板把每一项圈在一起，缩短视线在区块之间来回移动的距离。

- 四个分区各自是一块面板：`--surface-raised` 底色 + 1px `--line` 边界 + `--r-md` 圆角 + `--shadow-card`。面板之间用 `--sp-6` 间距，取代原先只有一条分隔线的 `--sp-8` 松散排布。
- 面板只承担分区，不承担层级：面板内部不再拆出子卡片，列表和表单仍用原有行结构。
- 分区块顺序固定为外观、数据管理、分类、键盘快捷键，危险区域排在最后；顺序变化会改变用户的肌肉记忆。
- 「危险区域」整块用 `1px solid var(--coral)` 边界包围，标题使用 `--coral`，说明写清清除范围、保留项和不可恢复性；按钮与说明在宽屏左右分列、窄屏堆叠。
- 危险区域只放「清除所有数据」这一个动作，不得把导出、导入或其他设置一并搬进来，避免警示色失去指向性。
- 面板内部的线与面板边界不重复：表单区与展示区之间只保留一条 1px `--line`（列表容器的上边线）；容器内最后一位不再画下边线，收尾交给面板自身的边界。
- 分类管理的表单走「placeholder 即标签」：保留 `.sr-only` 可访问名，可见标签折进输入框 placeholder（「输入新分类名称……」），输入框不再隔着大段空白与标签相认；「输入 + 创建」同排，表单宽度上限 560px，不让输入框把整行撑满。
- 创建是该表单行唯一的主行动，使用实心 `--teal` 的 `.button-primary`；线框样式会把「创建」降级成与其它次级动作同级的选项。

### 4.13.1 分类行与行操作图标

有数据时分类管理展示为只读行，不再每行常驻输入框：

- 行结构固定为「名称靠左、操作靠右」：名称一列可换行不被截断，重命名与删除两个图标按钮并排在行尾，删除作为高危动作固定占最右位置。
- 行高不低于 52px（32px 图标按钮上下各留一档），相邻行只用一条 `--line` 分隔，不逐行包卡片。
- 删除图标的 `:hover` 用 `--coral-soft` 底 + `--coral` 图标表达高危；铅笔与垃圾桶的形状承担非颜色识别，颜色只是第二重提示。
- 重命名走原地编辑：点铅笔后名称就地换成输入框，Enter 或 ✓ 保存，Esc 或 ✕ 取消，取消即重取数据回到只读；保存失败就地播报且保留编辑行。
- 删除仍走 §4.5 的迁移确认对话框；整段 `.category-list` 重建后焦点必须回到同一行的对应图标按钮，分类为空时退回创建输入框，不得丢到 `body`。
- 行内图标是本产品第一处行操作图标（§4.11「不引入图标」的约束仅限侧栏导航）：一律内联 SVG，不引入 SVG 资源文件或图标字体；24×24 画布、2px 线宽、`stroke="currentColor"`、无填充、展示尺寸 16px，深色主题随文字色自动切换；图标本身 `aria-hidden="true" focusable="false"`，动作名称全部由按钮的 `aria-label` 与 `title` 承担。

### 4.14 月历视图

月历回答“这个月的任务怎么分布”，因此视图本身要明确表达“正在看哪个月”，并与页面头部表达的“今天”区分开。

顶部月份导航：

- 月份标题是视图内唯一表达“当前查看月份”的地方，格式为 `2026年9月`；页面头部日期只表达“今天”，不重复月份视图。
- 上/下月按钮直接贴在月份标题两侧，形成 `‹ 2026年9月 ›` 一组；按钮用箭头图标，可访问名固定为“上个月”“下个月”，不因图标化而丢失名称。
- 月份标题保留稳定宽度，切换月份时不因字数变化而左右跳动。
- 不使用“上个月 / 下个月”两个文字按钮悬在标题另一侧：翻页控件必须与被翻页对象相邻。

快速记录：沿用 §4.2 的顺序「输入 → 计划日期 → 补充详情 → 记录」，主按钮在行尾。

日历单元格（桌面与窄屏同一套规则）：

- 任务标题单行显示，超出用省略号截断；完整标题写入 `title`，悬停和读屏都能拿到全文。
- 完成控件用圆角方形复选框（同 §4.3），星标与复选框、标题之间保留间距，不互相挤压。
- 每个单元格最多显示 3 条任务；超出的部分折叠为 `+N 更多` 按钮，点击打开当日任务弹窗。日期格右上角的数字仍表示当日任务总数。
- `+N 更多` 的可访问名包含日期与总数（例如“查看 9月22日 的全部 5 项任务”）；只有确实存在隐藏任务时才渲染该按钮。
- 同日任务弹窗列出当天全部任务，复用任务行的完成、编辑与“更多”操作；宽窄屏同一结构，Esc 与关闭按钮都可关闭，关闭后焦点回到触发它的 `+N 更多` 按钮。
- 弹窗打开期间任务状态变化时，弹窗内容随最新数据刷新；当天任务清空时自动关闭弹窗。

### 4.15 全部任务筛选区

筛选是“找回一件事”的辅助手段，不是要用户先填一张表单，因此条件必须渐进披露：

- **常驻只有「搜索」和「状态」两项**：回答“我要找什么”和“它现在处于什么状态”，覆盖绝大多数场景。
- 其余条件（日期区间、分类、标签、优先级、星标、资料）收进「高级筛选」，默认收起；展开后用一条细分隔线与常驻行分隔，字段排布与常驻行完全一致，不出现第二种排版。
- 触发按钮上用计数角标写明已启用的高级条件数（`已启用 N 项`，数字对读屏同样可读）：面板收起时条件仍在生效，不能无声无息地缩小结果集。
- hash 中带高级条件时（刷新、后退、收藏深链）面板自动展开；展开态本身不进 hash，它只是临时姿势，真正的状态是条件值。
- 「清空筛选」是纯文字按钮（主题色 + 下划线），不使用与下拉框相同的“浅底 + 边框”外形——那样会被读成又一个输入条件；且只在确实存在筛选条件时出现，无条件时不占位。
- 任务列表不使用斑马纹：任务之间只用一条 `--line` 细分隔线分隔，密度靠留白和字号层级建立。宽屏内容列沿用 `--content-measure` 上限并居中，避免视线在超长行上来回扫视。

## 5. 状态与 UX 文案

### 5.1 空状态

空状态必须回答“这里为什么为空”和“下一步做什么”，并且全产品共用同一结构与同一组件（`.empty-state`）：

```text
[标题]  当前状态        “今天还没有待办”
[说明]  原因或口径      一句话，可选
[动作]  唯一主入口      “记录第一件事”，可选
```

- 结构规则：标题一行、说明一行；只有确实存在可执行动作时才加按钮，且只加一个。
- 组件规则：页面级空状态统一使用 `.empty-state`；`.empty` 只用于行内或单元格级提示（月历格、任务编辑抽屉的次级区、子任务列表、某个日期没有任务）。
- 抽屉次级区的空提示必须通栏：容器是 flex 平铺（标签）时用 `flex: 1 1 100%` 撑满，否则它按内容宽度收缩，分隔线只到文字宽度，与资料、子任务两条通栏线在同一屏里长度不一。
- 同一屏只保留一处空状态：标题统计行与空状态卡片不得重复表达同一件事。
- 方位必须真实：文案里的“上方/下方”要与实际布局一致，否则改成不带方位的说法。
- 各页口径：今天无任务用“今天还没有待办”，明天/本周无计划用“明天还没有计划/本周还没有计划”，收集箱为空说明“想到的事情先放进来”，工作记录无数据显示“还没有完成记录”而不是 `0%`，资料为空要提供“添加资料”，回收站为空说明删除的任务会在这里等待处理。
- 今日计划确实存在且全部完成时，不复用“今天还没有待办”的空状态；使用带轻量庆祝插画的专属状态，表达“太棒了！今天的任务已全部搞定”，并保留顶部快速记录入口。
- 空状态不是只在首屏生效：受管列表从有行变为空时（完成、撤销、移入回收站等动作后），必须原地补回同一份页面级空状态，不得留下无文案无入口的空白区域。
- 规则模板总结的说明写用户价值（“在本机生成，不上传任何内容”）；“只使用本地统计和已完成任务标题生成纯文本”是实现约束，记录在本文档，不上界面。
- 总结生成后，复制入口固定放在总结文本框右上角的轻量图标按钮中，使用可访问名称“复制总结”；不在文本框下方另占一行。

### 5.2 加载与错误

- 加载文案使用“正在加载…”等带省略号的进行时表达。
- 错误文案包含问题和下一步，例如“任务没有保存。你的输入还在，请检查标题后重试。”
- 异步请求失败不能产生未处理 rejection，也不能用迟到的旧请求覆盖当前页面。
- 表单错误就近显示，提交后焦点进入第一个错误字段或错误摘要。

### 5.3 语气

- 使用主动、具体、短句：“保存任务”“打开工作台”“重新选择文件”。
- 数量使用阿拉伯数字；日期和时间使用本地格式化函数，不手写不一致的格式。
- 不用“系统异常”“操作失败”作为唯一信息；必须给恢复路径。
- 不用颜色单独传递“完成、逾期、危险”等状态。

### 5.4 术语表

同一概念只允许一种说法，动作词与状态词分开使用：

| 概念 | 唯一说法 | 避免 |
| --- | --- | --- |
| 从列表移除但可恢复的任务 | 移入回收站 | 删除、移除 |
| 不可恢复的任务删除 | 永久删除 | 删除 |
| 未安排日期的任务归处 | 收集箱 | 未分类、收件箱 |
| 任务没有计划日期 | 无计划日期 | 无时间、未安排 |
| 有计划日期但没定时间 | 无时间 | 无计划日期 |
| 任务所属的组织单元 | 分类 | 列表、分组 |
| 跨分类、可多选的属性 | 标签 | 列表、分类 |
| 正常结束的任务（状态） | 已完成 | 完成 |
| 用户主动放弃的任务（状态） | 已取消 | 取消 |
| 回收站里的任务（状态） | 已删除 | 移入回收站 |
| 快速新增后的回退 | 撤销创建 | 删除 |
| 删除资料对话框 | 删除资料 | 确认 |

- 动作按钮使用动作词，状态标签使用状态词，两者不得混用。
- 校验与错误提示只使用界面上的字段名（“任务名称”“开始时间”“截止时间”“计划日期”“描述”），不得出现 `title`、`startTime`、`dueTime` 这类内部字段名；提示要直接给出下一步，例如“截止时间必须晚于开始时间”“没有计划日期的任务不能填写时间，请先选择计划日期”。
- 修改术语时必须同步更新本表、相关测试断言与页面文案。

## 6. 响应式与主题

### 6.1 窄屏

- 目标验收宽度为 `390px`，核心流程不得横向溢出。
- Dashboard 侧栏转为顶部导航，快速记录改为纵向分组，任务行保持可操作高度。
- 抽屉和表单对话框使用可用全宽，主体内部滚动；不把关键字段隐藏到不可发现的区域。
- Toast、菜单和固定操作不能覆盖当前焦点或底部提交区域。
- 密度视图（例如月历格）也必须保留完整的任务操作入口：宁可让触发按钮占一点格子宽度，或改为点击任务行打开同一份“更多”菜单，也不得用 `display: none` 直接移除。
- 不通过缩小字号解决空间问题，优先调整布局和信息密度。

### 6.2 深色主题

- 使用 `color-scheme: dark`，原生滚动条、输入框、日期选择器和下拉列表必须跟随主题。
- 深色背景、表层、文字、边线和语义色都使用 `tokens.css` 的成对令牌。
- 检查 Toast、危险按钮、焦点环和遮罩在深色背景上仍有足够对比度。

### 6.3 离线与性能

- 运行时不依赖网络、第三方 CDN、远程字体或图标服务。
- 大列表避免在每次输入时做昂贵的全量布局读取；布局由 CSS Grid/Flex 处理，不用 JavaScript 测量位置。
- 任务标题、资料名称和错误文本必须处理长内容，允许换行、截断或折行，不得撑破容器。

## 7. 无障碍与交互验收

- 使用语义化 `header`、`nav`、`main`、`section`、`button`、`label`、`dialog`，不要用可点击的 `div` 或 `span` 代替按钮。
- 每个表单控件有可见标签、包裹标签或有意义的 `aria-label`；icon-only 按钮必须有 `aria-label`。
- 所有交互控件有清晰的 `:focus-visible` 焦点环，不能用 `outline: none` 隐藏焦点。
- 异步结果、Toast 和校验信息使用适合的 live region；不会因为颜色或动画才可理解。
- Tab 顺序遵循当前页面的阅读顺序；弹窗打开后焦点不逃出浮层，关闭后回到触发元素。
- Enter 提交主要表单，Esc 取消/关闭，按钮和选择控件同时支持鼠标、触摸和键盘。
- 控件使用 `touch-action: manipulation`；交互目标不低于产品统一的最小高度。
- 200% 缩放和 390px 宽度下仍能完成记录、完成、延期、删除和关闭弹窗。
- 减少动效时关闭非必要动画，不影响状态变化和操作反馈。
- 声明复合 ARIA 角色（`grid`、`listbox`、`menu`）时必须实现对应键盘交互：方向键在行/列/项之间移动，Home/End 到首尾，Esc 退出；没有实现就不要声明该角色。
- 页面级容器不使用 `aria-live`；只放在会变化的局部（结果、校验、列表数量），避免换页时整段播报。
- 月历不声明 `grid`/`gridcell`：格子内含完成、编辑、菜单等多个 Tab 停留点，与复合角色的箭头键浏览模式冲突；日期格用自身 `aria-label` 表达星期，方向键导航作为不加载复合语义的键盘增强保留。
- 同一屏内不允许出现两个可访问名称相同的按钮：同一个任务标题同时出现在“下一步”摘要和任务行时，摘要按钮使用动作名称（例如“下一步任务”），任务行按钮保留标题；在每行重复出现的动作入口（“更多任务操作”“永久删除”等）必须把任务标题写进可访问名。
- 需要补充语义时优先在按钮外表达（区域标题、`aria-describedby`）；确要覆盖按钮名称时，必须保证不丢掉用户需要的动作或对象信息。

## 8. 设计决策清单

新增组件前必须回答：

1. 这是用户当前必须完成的动作，还是可以渐进披露的辅助信息？
2. 它属于 Popup、抽屉、确认框、表单对话框、Toast 还是普通页面内容？
3. 用户失败或误操作后如何恢复？是否需要撤销或二次确认？
4. 键盘、读屏、窄屏、深色主题和长文本下是否仍然可用？
5. 是否引入了重复卡片、重复文案、额外颜色或不必要的浮层？
6. 是否复用了 `tokens.css` 和现有组件语义，而不是新增一套局部规则？

## 9. UI/UX 交付验收

每次涉及界面或交互的修改至少验证：

- 2 秒内能找到当前页面主任务和快速记录入口；
- Popup 标题输入到保存只需输入和一次 Enter；
- Toast 不遮挡输入、日期按钮、快速记录、底部操作和当前焦点；
- 删除、覆盖、永久删除和高风险操作都有产品内确认或可恢复路径；
- 弹窗长内容在视口内滚动，Esc、取消和关闭按钮行为一致；
- 空、加载、错误、成功和冲突状态都有明确文案和下一步；
- 颜色、图标和动效都不是唯一的信息来源；
- 390px、200% 缩放、深色主题和键盘流程无横向溢出或焦点丢失；
- 术语与 5.4 节的术语表一致，动作按钮和状态标签使用同一套唯一说法；
- 页面级空状态都使用 `.empty-state` 结构，同一屏不出现两处空状态；
- 声明复合 ARIA 角色的页面可用方向键完成基本导航（例如月历切换日期）；
- 390px 下月历等密度视图仍可完成、延期和删除任务；
- 表单校验错误出现在字段或表单旁，而不是只闪过全局提示；
- 抽屉存在未保存修改时，关闭前有确认；
- 运行时无外部请求、无控制台未处理错误，且现有单元/E2E 测试继续通过。

实现冲突时，优先保证用户任务流、可恢复性和可访问性，再处理视觉装饰；所有调整都应回写本规范或 README 的相关说明。

# WorkTodo V1.0 界面设计规范

> 状态：已确认方向（视觉方向 C、工作台构图 A、编辑方式 A）
> 日期：2026-09-17
> 适用范围：V1.0 Popup、今日工作台、任务列表、任务编辑器和空/错/成功状态

## 1. 设计意图

WorkTodo 面向在受限办公环境中使用 Chromium 的单人知识工作者。用户打开扩展时最重要的问题是“下一步做什么”，而不是浏览功能。

界面必须让用户形成三个连续动作：

1. 看到逾期与今天的重点；
2. 用一行文字快速记录新事项；
3. 在不离开今日主线的情况下完成、延期或打开详情。

视觉方向为 **清透网格**：薄荷灰底、暖白工作面、深墨绿文字、青绿色行动色。构图为 **任务主线**：今日任务占据 Dashboard 主要空间，导航收窄，低频功能后置。编辑方式为 **行内新增 + 轻抽屉**：只输入标题时立即保存，需要更多字段时再展开。

## 2. 视觉令牌

由于目标包含 Chromium 110+ 且完全离线，V1.0 不加载远程字体或 CDN；优先使用系统已有的中文字体。

### 2.1 颜色

~~~css
:root {
  --canvas: #e8f1ed;
  --surface: #fbfaf7;
  --surface-raised: #fffdf9;
  --ink: #183331;
  --muted: #6b7e7a;
  --line: #cfded8;
  --teal: #2c7a7b;
  --teal-soft: #e5f0ec;
  --coral: #e56d56;
  --coral-soft: #fae9e4;
  --focus: #1b6466;
  --disabled: #a7b5b0;
}
~~~

颜色语义固定：

- 青绿色只表示可执行的主行动、完成或正向进度；
- 珊瑚色只表示逾期、删除风险或需要立即关注；
- 分类与普通标签不使用大量彩色胶囊；
- 状态必须同时有文字或图标，不能只用颜色；
- 深色模式不在 V1.0 实现，不为此引入第二套视觉系统。

### 2.2 字体与字号

~~~css
:root {
  --font-sans: "Noto Sans CJK SC", "Source Han Sans SC",
               "Microsoft YaHei", sans-serif;
  --text-xs: 12px;
  --text-sm: 13px;
  --text-md: 14px;
  --text-lg: 18px;
  --text-xl: 28px;
}
~~~

- 正文使用 14px；列表辅助信息使用 12–13px；
- 今日页面标题使用 28px，Popup 标题不超过 18px；
- 任务标题最多两行，超出用省略号但详情可完整查看；
- 中文行高 1.5，数字和时间使用同一字体，避免对齐跳动；
- 不使用大号渐变标题、全页面等宽字体或远程字体。

### 2.3 间距、圆角与阴影

- 基础间距单位为 4px，常用值 8、12、16、24、32px；
- 主面板圆角 12px，按钮与输入框圆角 6px，避免所有元素都做成胶囊；
- 阴影只用于抽屉、Popup 浮层和 Toast：0 8px 24px rgba(24, 51, 49, .10)；
- 分隔优先使用留白和 1px 边线，不给每一行套卡片；
- 主内容最大宽度 960px，宽屏下保持左对齐，不把工作内容强行居中。

## 3. 工作台布局

~~~text
┌─────────────────────────────────────────────────────────┐
│ WORKTODO                                  9月17日 · 周四 │
├──────────────┬──────────────────────────────────────────┤
│ W            │ 今日工作                                  │
│ 今天         │ 完成 5 / 8 · 还剩 3 项                     │
│ 明天         │ 完成率 ━━━━━━━━━ 62%                       │
│ 本周         │                                            │
│              │ 逾期 · 1                                   │
│ 收集箱       │ □ 提交 XX 项目报价          逾期 / 延期 1次 │
│ 全部任务     │                                            │
│ 逾期         │ 今天 · 2                                   │
│ 已完成       │ □ 贵州项目报价              09:00–12:00    │
│              │ □ 联系 XX 客户              无时间         │
│ 统计         │                                            │
│ 设置         │ [记录一个新事项，按 Enter 保存……]       ＋ │
└──────────────┴──────────────────────────────────────────┘
~~~

- 侧栏宽度 208–224px，顶部固定产品标识，底部固定设置；
- 主区只有一个视觉主标题“今日工作”；
- 逾期区只在有逾期任务时出现，没有逾期时不保留空容器；
- 已完成任务默认折叠，展开后使用较低对比度；
- 快速新增固定在任务列表之后，不漂浮遮盖任务；
- 任务行只在悬停/键盘聚焦时显示次级操作，避免按钮噪音。

### 3.1 导航层级

V1.0 导航分组为：

- 计划：今天、明天、本周（本周可以先用列表视图）；
- 任务：收集箱、全部任务、逾期、已完成；
- 回顾：统计；
- 系统：设置。

当前路由通过青绿色短竖线、粗体文字和 aria-current=page 标识。导航项不是图标孤岛，每项都有文字。

### 3.2 今日页信息优先级

首屏严格按以下顺序：

1. 逾期任务；
2. 今日未完成任务；
3. 完成进度；
4. 已完成折叠区；
5. 快速新增。

月度图表、分类管理、备份和低频设置不得进入今日首屏。

## 4. Popup 设计

Popup 目标尺寸约 360 × 500px，适合工具栏点击后的快速确认，不承担完整编辑。

### 4.1 结构

~~~text
┌──────────────────────────────┐
│ 今日 · 9月17日        ↗ 工作台 │
│ 今天要做什么                   │
│ 完成 5 / 8 · 还剩 3 项         │
│ 完成率 ━━━━━━━━━ 62%            │
│                                │
│ 逾期 1                         │
│ □ 提交 XX 项目报价     逾期    │
│                                │
│ □ 贵州项目报价          09:00  │
│ □ 联系 XX 客户          无时间  │
│                                │
│ [记录一个新事项，按 Enter 保存] │
│ [今天] [明天] [收集箱]          │
└──────────────────────────────┘
~~~

- Popup 打开后标题输入框自动获得焦点；
- 默认只显示最多三个关注任务：逾期、星标、高优先级、最早时间；
- 逾期提示用珊瑚色和“逾期”文字，不使用红色大面积警报；
- 底部快捷日期为今天、明天、收集箱；自定义日期在 Dashboard 处理；
- “打开工作台”是次要文字按钮，不与“新增任务”争夺主行动层级。

## 5. 任务行与动作

### 5.1 默认任务行

每行包含：

- 真实 checkbox 或等价键盘控件；
- 任务标题；
- 计划日期/时间或“无时间”；
- 可选的优先级文字；
- 逾期文字和延期次数；
- 聚焦/悬停后出现的开始、延期、更多操作。

主操作顺序为：点击圆形 checkbox 完成；点击标题打开详情；更多菜单放置取消、删除和复制，避免误触。

### 5.2 状态样式

- todo：空心圆 + 普通文字；
- in_progress：青绿色短线 + “进行中”文字；
- completed：实心青绿色圆 + 删除线标题 + 完成时间；
- cancelled：灰化标题 + “已取消”文字；
- overdue：珊瑚色“逾期”标识 + 原计划日期，不改变整行背景。

## 6. 任务编辑器

### 6.1 行内新增

输入框占据列表尾部，placeholder：

> 记录一个新事项，按 Enter 保存……

行为：

- 输入标题按 Enter：立即创建收集箱任务，清空输入；
- 选择“今天/明天”后再按 Enter：任务直接带计划日期；
- 空标题、超过 200 字符或存储失败：输入保留，错误贴近输入框；
- 成功显示 5 秒 Toast：“已添加到收集箱 · 撤销”。

### 6.2 轻抽屉

需要描述、时间、优先级或分类时，从行内输入旁展开右侧轻抽屉，宽度 360–400px。抽屉不遮挡整个 Dashboard，顶部显示“新增任务”或任务标题。

首屏字段只显示：

1. 任务名称；
2. 计划日期；
3. 优先级；
4. 分类。

“描述、开始时间、截止时间”放在“更多信息”折叠区。抽屉底部固定“取消”和“保存任务”。

- 打开抽屉时焦点进入任务名称；
- Esc 或取消关闭抽屉并恢复触发元素焦点；
- 保存失败不关闭抽屉，不丢失用户输入；
- 修改已有任务时显示当前 revision 冲突提示，并提供“重新加载”和“复制为新任务”。

删除和覆盖导入使用明确的确认对话框；普通编辑不使用阻塞式确认。

## 7. 空、加载、错误与成功状态

### 7.1 今日无任务

标题：

> 今天暂时没有待办

说明：

> 先记录一件要做的事，日期和分类可以稍后安排。

主按钮：

> ＋ 添加第一个事项

### 7.2 收集箱为空

标题：

> 收集箱是空的

说明：

> 想到的事情先放进来，整理可以晚一点。

主按钮：

> ＋ 记录临时事项

### 7.3 存储或迁移错误

不显示技术错误码。统一结构：

> 任务没有保存  
> 你的输入还在。请重试；如果仍失败，请先导出备份并重新打开扩展。

按钮：重试、复制错误详情（仅复制非任务内容的诊断摘要）。

### 7.4 并发冲突

> 这个任务刚刚在另一个窗口更新过。  
> 保留你的修改，还是重新载入最新版本？

按钮：保留为新任务、载入最新版本。

### 7.5 成功反馈

Toast 不阻塞页面，显示动作和撤销：

- 已完成“贵州项目报价” · 撤销；
- 已延期到 9月18日 · 撤销；
- 已移入回收站 · 撤销；
- 已导出 128 个任务。

## 8. 动效

- 页面首次加载只对主内容做一次 120–180ms 的淡入和轻微上移；
- 任务完成使用 160ms 的 opacity/transform 反馈，不动画布局尺寸；
- 抽屉使用 ease-out，打开/关闭不超过 220ms；
- Toast 进入和退出只改变 opacity 与 transform；
- prefers-reduced-motion: reduce 时关闭非必要动画；
- 不使用弹跳、霓虹发光或持续装饰动画。

## 9. 无障碍与键盘

- 使用语义化 header、nav、main、section、button、label 和 dialog；
- 当前导航设置 aria-current=page；
- 任务状态必须有可读文本；checkbox 状态用 aria-checked 或原生控件；
- 每个 icon-only 按钮有 aria-label 和 tooltip；
- 弹窗打开后焦点进入标题字段，关闭后返回触发元素；
- Tab 顺序遵循：导航 → 今日摘要 → 任务列表 → 快速新增；
- Enter 保存，Esc 取消/关闭；N、F、T、W、M 在 V1.1 再加入；
- 键盘焦点使用 2px focus 外描边，不能隐藏 outline；
- 200% 缩放下不依赖横向滚动才能完成新增、完成和延期。

## 10. UI 交付验收

设计实现完成后必须同时满足：

- 在 2 秒内可找到今日首要任务和新增入口；
- Popup 标题输入到任务保存只需输入和一次 Enter；
- Dashboard 首屏不出现超过四个同级主行动；
- 没有任务时空状态给出下一步，而不是空白；
- 完成、延期、删除和导入失败都有明确反馈；
- 状态、优先级、逾期不依赖颜色；
- Chromium 110+ 离线加载无远程字体、图标或脚本请求；
- 视觉检查不出现纯黑/纯白大面积、渐变文字、玻璃拟态、重复卡片网格或发光装饰。

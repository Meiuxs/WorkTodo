# WorkTodo V1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** 交付一个可离线运行的 Chromium Manifest V3 扩展，使单个用户能快速记录、安排、处理和回顾本地工作任务。

**Architecture:** Popup 与 Dashboard 只负责界面和用户输入；领域服务负责状态机、校验、查询、统计和备份；IndexedDB 是任务、分类和事件的唯一事实来源，chrome.storage.local 只保存设置和轻量元数据。任务 revision 与 IndexedDB 事务共同阻止 Popup 和 Dashboard 的静默覆盖。

**Tech Stack:** Manifest V3、原生 HTML/CSS/ES Modules、IndexedDB、chrome.storage、Node.js 20+ 内置 `node:test` 单元测试、开发期 `@playwright/test` E2E 测试；产品运行时无 Node/npm 依赖、无构建步骤。

**Spec:** docs/superpowers/specs/2026-09-17-worktodo-v1.1.md

**Design:** docs/superpowers/designs/2026-09-17-worktodo-ui-design.md

## Global Constraints

- 目标平台是 Chromium 110+、统信 UOS、ARM64；使用 Manifest V3。
- 产品运行时仅用 HTML、CSS、JavaScript 和 Chromium Extension API，不依赖 Node.js、npm、服务器、数据库程序或网络；Node.js 与 `@playwright/test` 仅用于开发期自动化测试。
- 不声明 host_permissions；不读网页、历史、密码、Cookie 或剪贴板；不加载 CDN、远程脚本或远程样式。
- V1.0 manifest 仅申请 storage；提醒、通知、alarms、downloads 和 unlimitedStorage 不在首发实现。
- 任务主数据存 IndexedDB；chrome.storage.local 只保存设置、schema 版本和最近导出时间。
- 日期为 YYYY-MM-DD，时间为 HH:mm，时间戳是含时区的 ISO 8601；业务日期使用系统本地时区。
- 生命周期只能为 todo、in_progress、completed、cancelled；删除使用 trashedAt，不能新增 deleted 状态。
- 本计划不实现标签、子任务、重复任务、月历、提醒、回收站页面、自动快照、CSV、深色模式或高级快捷键。
- 已确认视觉方向为“清透网格”，工作台构图为“任务主线”，任务编辑为“行内新增 + 轻抽屉”；所有颜色、字号、间距和状态文案以 Design 文档为准。
- 不使用纯黑/纯白大面积、渐变文字、玻璃拟态、发光装饰或重复卡片网格；状态、优先级和逾期不能只用颜色表达。
- 每一任务先写失败测试，再写最小实现；任务结束时只暂存该任务文件并提交。
- 单元测试必须覆盖领域、数据、服务、查询/统计、备份与控制器的关键规则；E2E 必须覆盖核心用户闭环、并发冲突、重启持久化与无外部请求。
- E2E 工具只作为 devDependency 固定版本，不得进入扩展打包产物；测试使用隔离的 Chromium 配置目录，不读写用户真实浏览器数据。

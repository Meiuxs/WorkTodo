# WorkTodo V1.1 Program Plan

> **For agentic workers:** Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` for each child plan below. Do not execute two dependent plans in parallel.

**Goal:** 把 V1.1 的标签、子任务、计划视图、重复任务、回收站、CSV、深色模式和快捷键拆成可独立交付、独立测试、独立提交的子计划。

**Architecture:** 先完成 schema v2 和兼容迁移，再让组织能力、计划视图、重复任务和数据体验分别建立在同一领域模型上。每个子计划完成后都必须形成可运行、可测试的产品状态，不能留下只在后续计划才可用的半成品接口。

**Tech Stack:** Manifest V3、原生 HTML/CSS/ES Modules、IndexedDB、`chrome.storage.local`、Node.js `node:test`、开发期 `@playwright/test`。

**Spec:** `docs/superpowers/specs/2026-09-17-worktodo-v1.1.md`

**Baseline:** `feat/worktodo-v1.0` 的 V1.0 实现，当前验证为 78 个单元测试和 8 个 Chromium E2E 通过。

| 2A | `2026-09-17-worktodo-v1.1-organization.md` | 标签编辑器与筛选、单层子任务和父任务完成确认 | foundation |

## 明确不在 V1.1 子计划中

提醒、工作日早晚提醒、自动本地快照、拖拽、番茄钟、耗时记录、项目模板、看板、甘特图和高级报表仍属于 V1.2 或更后版本。它们不能借 V1.1 任务顺带实现。

## 执行规则

- 每个子计划单独建立工作分支或继承同一 V1.1 工作分支，但任务提交必须按计划边界可回退。
- 先运行 foundation 的完整单元测试，再启动 2A、2B 和 2C 的 D1-D4；planning 合并后再执行 2C 的 D5-D6。
- 任何 schema 改变都必须同时修改导出、导入、IndexedDB 迁移和旧备份回归测试。
- 所有新增功能必须在键盘、非颜色化状态和 390px 视口下可操作。
- 不新增 `downloads`、`alarms`、`notifications`、`unlimitedStorage` 或 host permissions。

## 最终集成门禁

全部子计划合并后执行：

```bash
npm test
```

Expected: 单元测试与 Chromium E2E 全部通过；E2E fixture 继续断言运行期无外部网络请求。

同时检查 `manifest.json` 未新增权限或 host permissions，并确认 JSON/CSV 导出、导入、回收站、重复任务、周/月视图、深色模式和快捷键在同一个 V1.1 工作分支上可组合运行。

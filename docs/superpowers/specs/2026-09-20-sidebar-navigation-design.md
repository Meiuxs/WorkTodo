# WorkTodo 侧栏导航与设置入口设计

> 状态：待实施
> 日期：2026-09-20
> 关联规范：`docs/superpowers/designs/2026-09-17-worktodo-ui-design.md`
> 关联实现：`src/dashboard/index.html`、`src/dashboard/index.css`

## 1. 目标

收敛 Dashboard 侧栏导航的结构与视觉层级，重点解决设置入口"孤立、位置飘、和主条目长得一样"的问题，并清掉窄屏媒体查询里真正重复的声明。

本次不改变任何路由、页面内容、数据模型和离线能力，只调整导航的外壳。

## 2. 现状与问题

侧栏当前结构（`src/dashboard/index.html:14-48`）：

- 品牌区；
- `<nav class="nav" aria-label="工作台导航">`（19-43 行）内含无标签的「今天」主入口与三组：计划（明天/本周/月历）、任务（收集箱/资料收集箱/全部任务/已完成/回收站）、回顾（工作记录）；
- `<div class="nav__footer">`（44-47 行）内含「系统」标签与「设置」按钮。

具体问题：

1. **设置入口不在导航地标内。** `.nav__footer` 是 `<nav>` 的兄弟而非子元素，读屏用户用"跳转到导航"取不到设置入口。这是现存的无障碍缺陷。
2. **「系统」标签与内容重量倒挂。** 一个分组标签只带一个条目，标签（12px 灰字）的存在感压过了它要分隔的内容。
3. **`margin-top: auto` 造成"位置飘"。** 设置被推到侧栏最底部。侧栏内容约 600px 出头，在 1000px 高的窗口里，设置会停在离「工作记录」两百多像素处，孤立且难以预期。
4. **同一个组件有两套选择器。** `.nav__settings` 是 `.nav button` 的平行复制品：布局、hover、选中态在 `src/dashboard/index.css:66-116` 与 `.nav__settings` 规则组里各写一遍，改一次要改两处。
5. **窄屏媒体查询历史叠加。** `index.css:1136-1204` 与 `1213-1243` 是两段 `@media (max-width: 680px)`，其中 10 个选择器重复或冲突，后一段覆盖前一段。

## 3. 决定

### 3.1 设置不吸底，跟随导航末尾

设置按钮紧跟在「工作记录」之后，上方一条分隔线。间距沿用现有刻度：分隔线距「工作记录」一个分组间距 `--sp-6`（20px），按钮距分隔线 `--sp-4`（12px）。

- 被否决：保留吸底（`margin-top: auto`，或改用 `position: sticky; bottom: 0`）。它能让设置永久可见，但高屏窗口下设置仍会离导航很远，正是问题 3 的成因。
- 代价：窗口高度低于约 800px 时，设置需要滚动一屏才能看到。设置是低频目标，可以接受。
- 副收益：不引入滚动包装层，窄屏布局因此一行都不用改（见 4.4）。

### 3.2 侧栏不加图标

明确决定：本次不为侧栏条目引入任何图标或 SVG 资源。

- 11 个条目里有四对近义项（明天/本周、收集箱/资料收集箱、全部任务/已完成、工作记录）。图标只有在语义唯一时才降低扫视成本，四对互相混淆的象形图反而增加判断成本。
- `2026-09-17-worktodo-ui-design.md` §4.9 刚做过反向决定：撤掉侧栏条目上的 `kbd` 徽标，理由是"避免侧栏和表单里散落零散提示"。图标属同类视觉噪声。
- 权威规范 §6.3 要求"运行时不依赖网络、第三方 CDN、远程字体或图标服务"，图标只能手写内联 SVG。当前全项目零图标（唯一近似物是 `index.html:91` 的关闭字符 `×`），只给侧栏加图标会让侧栏成为界面上唯一的图形区。
- 图标不解决本次目标：主条目与设置都有图标时重量仍然相同，建立层级差的是分隔线与弱化色。

若将来要引入整套应用图标语言，应作为独立决策处理，需定义图标集、尺寸、线宽、深色主题处理和 `aria-hidden` 规则。

## 4. 设计

### 4.1 结构与地标

把 `.nav__footer` 从 `<nav>` 的兄弟移入 `<nav>` 内部，位于「回顾」分组之后：

- 设置入口进入 `工作台导航` 地标，修复问题 1；
- 不引入任何滚动包装层，`.nav` 保留 `overflow-y: auto`（`index.css:40-48`），分组与设置处于同一个滚动流；
- `data-route` 属性、`markCurrentRoute()`、`createNavBadges()` 全部不变，`src/dashboard/index.js` 零改动。

### 4.2 视觉层级

- 删除 `<p class="nav__label">系统</p>`；
- `.nav__footer` 改为 `border-top: 1px solid var(--line); padding-top: var(--sp-4);`，删除 `margin-top: auto`（`index.css:52`）；
- 设置条目的高度（`44px`）与字号（`--fs-nav-item`）保持不变，层级差只由颜色承担：默认 `--muted`，`:hover` 回到 `--ink`，`[aria-current="page"]` 回到 `--teal`。

依据：权威规范 §6.1 要求"不通过缩小字号解决空间问题"，且 44px 触控目标不应降级。`--muted` 在浅色 canvas 上为 4.95:1（`src/styles/tokens.css:13-14` 已记录），深色主题 `#a5b8b3` on `#10201f` 约为 8:1，弱化后仍满足 WCAG AA。

分隔线用 `--line`。按 `tokens.css:15` 的定位，它属于"结构分隔线：纯装饰，不承担控件边界职责"，因此不适用 3:1 控件边界要求。

### 4.3 选择器收敛

- 删除 `.nav__settings` 类名（`index.html:46`）与 `index.css:112-116` 的独立声明块；
- 底部按钮并入 `.nav button` 那一组选择器，层级差异改由结构表达：`.nav__footer button`；
- 不新增 `data-variant` 之类的属性——"住在 footer 里"本身就是层级声明，少一个需要维护的约定。

已核对 `nav__settings` 只出现在 `index.html` 与 `index.css`，无 JS 与测试依赖，删除类名安全。

### 4.4 窄屏与媒体查询清理

审计结论：两段 `@media (max-width: 680px)` 中真正重复或冲突的只有下列 10 个选择器，其余 60 余条属于两块各自负责不同组件、并不重复。因此只清理重复部分，**不把两段硬合成一段**——硬合并需审计 390px 下几乎每个页面，会把一次侧栏修改变成全站窄屏回归。

| 选择器 | 现状 | 处理 |
| --- | --- | --- |
| `.app` | A 段 `grid-template-columns: 1fr`（`.app` 为 flex，死声明），B 段 `display: block` | 删 A 段 |
| `.sidebar` | A 段 7 条属性生效，B 段补 `flex: none` | 合并进 B 段 |
| `.nav` | A 段 `grid-template-columns`（死声明）+ `overflow: visible`；B 段 `flex-direction: row` 等 | 删 A 段（`overflow: visible` 在 `height: auto` 下与 base 无差异） |
| `.nav__label` | A 段 `display: none`，B 段按 `.nav__group` / `.nav__footer` 限定 | 删 A 段；B 段简化为 `.nav__label { display: none }`（footer 内已无 label） |
| `.nav button` | 两段几乎逐条重复（B 段多 `flex: 1 1 auto`） | 删 A 段 |
| `.nav button[aria-current="page"]` | 仅 A 段有 | 保留——窄屏下边框选中态的唯一来源 |
| `.nav__settings` ×2 | 两段各一条，B 段已覆盖 A 段 | 两条全删（类名已并入） |
| `.content` | A 段 `padding: … 140px`，B 段 `… var(--sp-7)` | 删 A 段，并列入 390px 视觉核验（140px 原意是给两行快速记录栏让位） |
| `.history-report-top` | 两段完全同值 | 删 A 段 |
| `.brand` / `.brand-lockup` | 非重复，但底边距可能叠加为 8px | 不自行改，合并时实测确认后再定 |

窄屏导航的横向 wrap 排布（`index.css:1219-1220`）保持不变，因为没有插入包装层。

## 5. 规范冲突与取代

- `docs/superpowers/specs/2026-09-18-worktodo-ux-v1.1-design.md:56` 写"侧边栏分成'今天''计划''任务''回顾''系统'五组"，同文件 82 行验收标准写"侧边栏能明确区分今天、计划、任务、回顾和设置"。本次把「系统」从具名分组改为分隔线 + 设置条目，**该表述被取代**。
- 同一份 spec 另有一处既有偏差：它写「今天」归入「计划」，而实现中「今天」是无标签主入口，`计划` 只含明天/本周/月历（`index.html:20-29`）。本次不改变该行为，但会在权威规范中写明实际分组，消除歧义。
- 权威规范 `docs/superpowers/designs/2026-09-17-worktodo-ui-design.md` 当前没有定义侧栏分组结构的章节（仅有 §4.9 角标）。实施时新增「侧栏导航与设置入口」一节，作为分组结构的唯一定义来源。

## 6. 验收

- **键盘**：Tab 顺序等于 DOM 顺序（四个分组 → 设置）；设置仍可用 Enter/Space 激活；`T / W / M / N / F` 与 `aria-keyshortcuts` 不变；不新增 tabindex。
- **读屏**：设置入口位于 `工作台导航` 地标内；删除「系统」标签后设置的可访问名仍为"设置"；角标 `aria-describedby` 行为不变。
- **对比度**：浅色 `--muted` on `--canvas` = 4.95:1；深色 `#a5b8b3` on `#10201f` 约 8:1；分隔线按装饰性 1px 线处理。
- **390px**：导航排布与现状一致；无横向溢出；确认从 A 段删除 `.content` 的 140px 底部内边距后，最后一条任务不被快速记录栏遮挡。
- **200% 缩放与深色主题**：无横向溢出；分隔线在深色下（`--line: #31504b`）可见。
- **静态**：无新增权限、无网络请求、无第三方资源（不引入图标，因此无 SVG 资源）。
- 现有单元测试与 E2E 测试继续通过；`tests/e2e/ux-refactor.spec.js:53-54`（today 与 month 字重断言）不受影响。

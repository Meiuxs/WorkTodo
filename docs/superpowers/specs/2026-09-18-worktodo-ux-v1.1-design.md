# WorkTodo V1.1 UX 优化规格

## 目标

从用户视角重新梳理 WorkTodo 的核心工作旅程：

> 临时事项 → 三秒记录 → 今日聚焦 → 完成/延期/取消 → 工作回顾

本次优化不改变任务数据模型、离线能力或已有 V1.1 功能，只改善信息架构、交互优先级、文案和视觉节奏。

## 目标用户与场景

用户是受限办公环境中的单人知识工作者。主要场景是：

1. 在工作中途快速记下一件事，不打断当前工作。
2. 早上打开工作台，快速判断今天先做什么。
3. 处理中持续完成、延期或取消任务，并能撤销误操作。
4. 周末或月底回顾实际完成的工作。

## 主要问题

### 信息架构

当前侧边栏把计划、任务、回顾入口放在同一扁平层级，用户需要自己建立心智分类；“今天”和“全部任务”的主次关系不够明确。

### 今日处理

今日页已经能展示进度和任务，但“最该先做什么”的主线不够突出，任务操作的主要动作和次要动作层级不够明显。

### 新建与编辑

快速新增是正确的入口，但“更多字段”打开的编辑器包含分类、标签、时间、子任务和重复规则，复杂度集中在一个抽屉中；首次使用者需要更清楚地知道哪些字段现在必须填、哪些可以稍后补。

### 回顾

工作记录页同时展示指标、总结和明细，信息完整但结论不够先行；未生成总结时的大块空文本框会制造视觉重量。

## 设计原则

1. **行动优先**：每个页面首屏只回答“现在下一步是什么”。
2. **渐进展开**：默认只展示标题、日期和状态；高级信息按任务需要展开。
3. **不丢数据**：所有动作都保留撤销、取消或恢复路径。
4. **少找一步**：用户不应为了记录、完成、延期或回顾而跨多个页面寻找入口。
5. **清透网格**：延续暖白、薄荷灰、深墨绿、青绿行动色和珊瑚提醒色；不用渐变、发光或堆叠卡片。

## 目标用户旅程

### 1. 记录

- Popup 与 Dashboard 都以标题输入为第一焦点。
- Enter 立即保存到收集箱；日期选择是可选的次级动作。
- 保存后显示“已添加到收集箱/已安排到某日”，提供撤销，并明确“打开工作台”入口。

### 2. 规划

- 侧边栏分成“今天”“计划”“任务”“回顾”“系统”五组。
- 今天、明天、本周、月历归入计划；收集箱、全部任务、已完成、回收站归入任务。
- 当前页面仍保持单一主标题，导航分组只提供方向，不增加新路由。

### 3. 处理

- 今日页按逾期、今天任务、已完成折叠区分组。
- 每个任务行的完成控件保持最大、最明确；延期作为高频次级动作，危险操作保持在更多菜单中。
- 空状态提供直接行动，而不是只显示“没有任务”。

### 4. 编辑

- 抽屉首屏只放任务名称、计划日期、优先级和星标。
- 标签与分类放在“组织”区域；描述、时间、重复规则和子任务按需展开。
- 重复规则用用户语言表达，如“每周一次”，避免一打开就暴露内部字段。
- 校验失败时抽屉保持打开，焦点回到出错字段。

### 5. 回顾

- 工作记录先显示日期范围和一句结论，再显示指标。
- 总结区域默认是轻量提示，生成后才显示文本框和复制操作。
- 指标继续保留，但通过分组和标题区分“实际完成”和“按计划”。

## 验收标准

- 首次打开 Dashboard 后，用户能在 3 秒内找到标题输入框并完成一条收集箱任务。
- 侧边栏能明确区分今天、计划、任务、回顾和设置，不改变现有路由功能。
- 今日页首屏能明确看到完成进度、逾期提示和下一步任务。
- 编辑器默认不展示全部高级字段，仍可完成标签、子任务和重复任务创建。
- Popup 新增后能看到成功反馈、撤销入口和打开工作台入口。
- 工作记录未生成总结时不显示大块空白编辑区域。
- 390px 视口无横向溢出；键盘流程、焦点和 Esc 行为保持可用。
- 不改变 IndexedDB、Manifest 权限、离线和无外部请求约束。

# WorkTodo 任务详情抽屉首屏设计

> 状态：待实施
> 日期：2026-09-20
> 关联规范：`docs/superpowers/designs/2026-09-17-worktodo-ui-design.md`（本次改写其 §4.4）
> 关联实现：`src/dashboard/index.html`（`#task-editor`）、`src/dashboard/task-editor.js`、`src/dashboard/index.css`

## 1. 目标

把任务详情抽屉的首屏从"一屏装不下的字段墙"收敛为"三行字段 + 一列可展开的入口行"，让人打开抽屉后不滚动就能看清这条任务的现状，并知道该改哪一项。

本次不新增字段、不改领域模型、不新增用户能力，只重排抽屉的信息架构与呈现方式。

## 2. 现状与问题

抽屉当前结构（`index.html` 的 `#task-editor`）：

```
任务详情 / 新增任务
先确定        任务名称 · [计划日期 | 优先级]
组织任务      列表(下拉) · 重复任务(fieldset) · 标签(checkbox 平铺 + 新建)
              相关资料(N 条，可添加/解除)
              标记为星标
需要时再补充   ‹details 更多信息› 描述 / 开始时间 / 截止时间
              子任务(仅已有父任务时)
底部固定      取消 · 保存任务
```

问题不是"缺功能"，而是**实现偏离了已批准的规范**。权威规范 §4.4 原文要求：

- 首屏字段只放任务名称、计划日期、优先级和分类；
- 描述、开始时间、截止时间、重复规则和资料放入折叠或次级区域。

对照实现：

| §4.4 要求 | 实现现状 |
| --- | --- |
| 首屏只放 名称 / 计划日期 / 优先级 / 分类 | 这四项在首屏，但**重复、标签、资料、星标、子任务也都直接展开** |
| 重复规则放入折叠或次级区域 | 未折叠，`fieldset.recurring-picker` 一直展开 |
| 资料放入折叠或次级区域 | 未折叠，`section.editor-resources` 一直展开（仅数量为 0 时隐藏） |
| 描述 / 开始 / 截止时间折叠 | 已折叠在 `details.editor-more` 内 |

即：唯一被折叠的是"更多信息"，而重复、标签、资料、子任务反而全部摊开——与规范意图相反。

用户在评审中确认的痛点是：**首屏太长、重点不清，要滚动才看得完，找不到"先改哪一项"。**

另有两处相关观察：

- 「标记为星标」作为一行独立 checkbox 夹在"相关资料"和"需要时再补充"之间，既不属于组织信息也不属于补充信息。
- 抽屉里存在两套折叠外观：`details.editor-more` 与 `section.editor-resources` 的标题结构不一致。

## 3. 决定

### 3.1 采用方案 A：每个次级区一行可展开的入口行

被否决的方案：

- **方案 B（两级结构，一个"整理这条任务"入口）**：首屏更短，但要么全开要么全关；"只想加个子任务"也要展开整块，展开后又回到一屏长内容，等于把问题推后一步。
- **方案 C（分 Tab）**：Tab 会隐藏内容并抬高键盘与读屏成本（需要 tablist 语义与方向键），也与规范 §4.8 刚做过的"菜单不再嵌套、保持扁平"的决定相冲突。

### 3.2 首屏只保留名称、计划日期、优先级

用户在评审中选择了最收敛的一档。这意味着 **§4.4 中"首屏含分类"被取代**：列表改为收起区的入口行。因此本次必须同步改写 §4.4，属于 `AGENTS.md` 要求的"先更新规范再修改组件"。

### 3.3 星标移到名称行右侧

星标是布尔开关，不适合做成折叠组。移到任务名称右侧做成 `☆` / `★` 切换，省掉一整行，并把高频旗标放到用户注意力已经在的位置。

### 3.4 不动"重复任务"的可编辑范围

领域模型里没有"这条任务是否重复"的字段：重复由独立模板实体加任务上的 `seriesId` / `occurrenceKey` 表达（`src/domain/task.js:109-110,155-156`），抽屉里的 `recurringPicker` 本质是创建时控件。让已有任务可改重复需要领域与服务层改动，超出本次"首屏重排"的范围。因此保持现状：**重复入口行只在新增任务时出现**，已有任务不显示该行。

### 3.5 不使用图标资源

`☆` / `★` 是文本字符，与项目现有做法一致（关闭按钮用 `×`，折叠指示用 `▸` / `▾`）。本次不引入任何 SVG 或图标字体。

## 4. 设计

### 4.1 首屏结构

抽屉 body 的顺序：

```
任务名称                          [☆]
先填标题和计划日期，其他可以稍后补。          ← 保留 .field-hint
[计划日期 | 优先级]
──────────────────────────────────
列表      工作                            ▸
标签      3 个                            ▸
重复任务  不重复                          ▸   （仅新增任务时出现）
资料      2 条                            ▸
子任务    2/5 完成                        ▸   （仅已有父任务时出现）
更多信息  已填写                          ▸
──────────────────────────────────
[冲突面板（出现时）]
底部固定：取消 · 保存任务
```

- **删除三个 `.drawer-section-label` 分区标题**（"先确定" / "组织任务" / "需要时再补充"）。分组由入口行本身承担；保留分区标题会多占两行高度，并把已收起的结构再说一遍。
- 保留 `field-hint`："先填标题和计划日期，其他可以稍后补"在收起之后更贴切。
- 计划日期与优先级沿用现有 `.field-grid` 布局，不改。

### 4.2 入口行的组件与摘要

- 一行一个 `<details class="editor-group">`：`summary` 左侧为组标签，右侧为当前值摘要，展开后是原有控件。
- **统一折叠词汇**：把现有 `.editor-more` 迁移为 `.editor-group`，全抽屉只保留一套折叠外观。`.editor-more` 仅被 `index.html` 与 `index.css` 引用，`task-editor.js` 与测试均不引用，改名安全。
- 行间细线由"容器 `border-top` + 每行 `border-bottom`"共享，避免相邻行叠加成双线。
- 各组摘要定义：

| 组 | 收起时显示 | 展开后内容 | 出现条件 |
| --- | --- | --- | --- |
| 列表 | 当前列表名 / 「未归入列表」 | 原下拉 | 始终 |
| 标签 | 「N 个」/「未添加」 | 标签平铺 + 新建标签 | 始终 |
| 重复任务 | 「不重复」/ 频率文案 | 原 `fieldset` | 仅新增任务 |
| 资料 | 「N 条」/「无」 | 资料列表 + 添加资料 | 始终 |
| 子任务 | 「已完成数/总数 完成」/「无」 | 子任务列表 + 添加子任务 | 仅已有父任务 |
| 更多信息 | 「已填写」/「未填写」 | 描述 + 开始时间 + 截止时间 | 始终 |

- **收起不丢信息**是本节的核心要求：摘要必须随编辑**实时更新**——改列表下拉、勾选标签、增删子任务或资料后立即重算，否则收起等于藏信息。
- 含 `fieldset` 的组（重复任务、标签）保留其 `<legend>`，但给 legend 加 `sr-only` 让它只对读屏可见，可见标题由 `summary` 承担。理由：`<legend>` 必须是 `<fieldset>` 的子元素，不能真的搬进 `summary`；这样既保留了 fieldset 的分组语义，又不会出现两个可见标题。

### 4.3 交互与无障碍

- 默认**全部收起，不记忆**展开状态：每次打开表现一致、可预期。
- 键盘：Tab 依次到达每个 `summary`，Enter/Space 展开，展开后 Tab 进入内部控件；Esc 仍然是关闭抽屉，不与折叠冲突。
- 星标的可访问性：
  - `<input type="checkbox" class="sr-only">` 承担语义、键盘与表单取值（`readChanges()` 继续读 `field(form, 'starred').checked`，表单契约不变）；
  - `☆` / `★` 字形 `aria-hidden`，可访问名由 `sr-only` 文本提供，并随状态改为「标记为星标」/「已标记为星标，点击取消」——**形状变化不能是唯一的信息来源**；
  - 焦点环用 `:focus-within` 呈现；热区高度与标题输入框一致，避免点空。
- **一条规则**：任何把焦点或注意力移入收起区的路径，必须先展开该组。
- **顺带修复（已获用户确认）**：并发冲突面板位于抽屉底部，收起改造后更容易落在视口外——用户只看到底部一行报错，却不知道有"保留为新任务 / 载入最新版本"两个出口。修法：冲突面板出现时滚入视野并聚焦「载入最新版本」。

### 4.4 数据流

抽屉不需要新的数据源：

- 列表摘要读 `category.options[category.selectedIndex]` 的文本；
- 标签摘要读 `selectedTagIds().length`；
- 子任务摘要来自 `subtaskService.list(currentTask.id)` 的已完成数与总数（`renderSubtasks()` 已经拿到这份数据）；
- 资料摘要来自 `resourceService.listForTask(currentTask.id)`（`renderResources()` 已经拿到）；
- 更多信息摘要读 `description` / `startTime` / `dueTime` 三个控件的值；
- 重复摘要读 `recurring.checked` 与频率下拉。

摘要重算收敛到一个函数，由现有的 `input` / `change` 监听与各区域渲染函数调用。

## 5. 规范冲突与取代

- 权威规范 §4.4 "首屏字段只放任务名称、计划日期、优先级和分类"**被取代**：分类移入收起区。
- `docs/superpowers/specs/2026-09-18-worktodo-ux-v1.1-design.md` 中"抽屉首屏只放任务名称、计划日期、优先级和星标。标签与分类放在'组织'区域"的表述**由 §4.4 取代**（星标不再是独立一行，也不是首屏字段，而是名称行上的开关）。该文件作为历史版本规格保留，不修改。
- 权威规范 §4.4 需新增：入口行必须带当前值或计数摘要；折叠只用一套词汇；默认收起不记忆；焦点或注意力移入收起区前必须先展开。

## 6. 验收

- **首屏**：打开抽屉（新建与已有任务各一次）不滚动即可看到并操作任务名称、计划日期、优先级三项；六个次级区默认全部收起（`details[open]` 数量为 0，重复/子任务行按其出现条件显隐）。
- **摘要实时更新**：改列表 → 摘要变；勾选标签 → 摘要变；新增或完成子任务 → 摘要变；关联资料 → 摘要变。
- **键盘**：Tab 可依次到达每个 `summary`；Enter 与 Space 都能展开；展开后内部控件可聚焦；Esc 关闭抽屉的行为不变。
- **星标**：点击后复选框的 `checked` 状态随之翻转、`sr-only` 文案同步改为「已标记为星标，点击取消」，`★` / `☆` 字形随之切换；保存后 `starred` 正确持久；仅用键盘（Tab + Space）也能切换。
- **对比度与主题**：深色主题下入口行细线（`--line`）仍可辨；`--muted` 摘要文字满足 AA。
- **390px**：无横向溢出；入口行与展开后的控件都可操作。
- **冲突面板**：出现时在视口内可见，焦点落在「载入最新版本」。
- **回归**：既有单元测试与 E2E 全部通过（受影响用例需在点内部控件前先展开对应组）。

## 8. 范围边界

明确不做：

- 不改领域模型、不改服务层，不让已有任务可编辑重复规则。
- 不新增、不改名、不删除任何表单字段与 `name` 属性；提交时的 `readChanges()` 契约不变。
- 不引入图标资源或 SVG。
- 不改抽屉宽度（`min(420px, 100%)` 与 1600px 下的 460px 保持现状）、不改底部固定操作区、不改并发冲突的两个出口语义。
- 不改 Popup。
- 不为入口行增加"记住展开状态"。
- 不合并 390px 断点下的既有声明。

## 9. 待实施时确认的手工项

- `☆` / `★` 字形在目标平台（Windows 与统信 UOS）的 CJK 字体栈里是否存在并被正确渲染。这是本次唯一无法自动断言的一点：自动化测试只能断言字符与状态，不能断言字形存在。

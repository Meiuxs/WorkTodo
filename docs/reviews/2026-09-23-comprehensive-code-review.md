# WorkTodo 全项目代码与 UX 审查报告

## 1. 审查结论

审查日期：2026-09-23

本轮覆盖运行时代码、IndexedDB 数据边界、任务与子任务生命周期、跨窗口编辑、备份导入导出、Popup、Dashboard、键盘与读屏语义、响应式布局、Manifest V3 权限/CSP、测试并发稳定性和发布包内容。

结论：未发现 P0 阻断问题。发现并修复 2 个 P1 数据/交互风险，以及 1 个 P2 测试稳定性问题；UX、无障碍、安全边界和打包策略未发现新的阻断问题。

审查按业务与数据、安全与发布、测试与运行时、UX 与无障碍四个角色拆分执行，并结合 CodeGraph、直接源码检查、单元测试、E2E、语法检查和发布包校验完成复核。并行代理本轮未在约定时间内返回有效报告，因此最终结论仅采用主工作流实际取得的代码与测试证据，不把未返回的代理结果当作证据。

## 2. 发现与修复

### P1：跨窗口编辑的冲突提示可能滞后

问题：编辑器使用防抖自动保存时，另一个 Dashboard 窗口先写入同一任务，当前窗口只刷新列表，不会立即提交已有草稿；冲突提示可能要等防抖定时器触发，重负载下还会错过首屏交互时机。

修复：

- `editor-autosave` 增加 `flushOnExternalChange()`，外部 `TASK_CHANGED` 到达时立即提交待保存草稿。
- `task-editor` 增加 `handleExternalChange()`，只处理当前任务，并保留既有 ConflictError 面板渲染路径。
- Dashboard 消息入口先唤醒编辑器保存，再刷新控制器。
- 增加防抖草稿遇到外部变更时立即提交的单元回归测试。

结果：两个 Dashboard 并发编辑用例在默认 2 worker 配置下稳定通过，冲突面板可见且焦点落在“载入最新版本”。

### P1：父任务级联恢复会先改子任务再发现父版本过期

问题：级联恢复先逐个恢复已完成子任务，随后才恢复父任务。父任务 revision 已过期时，子任务可能已经被修改，再依靠补偿恢复，造成额外 revision 和事件变化。

修复：

- 将 `ConflictError` 提升到 `src/domain/errors.js`，仓库继续导出兼容入口。
- `completeParent` 与 `restoreParent` 都在读取子任务前校验父任务 revision。
- 增加过期 revision 下“子任务保持原状态且 revision 不变”的回归测试。

结果：过期父任务会在任何子任务写入前失败；级联恢复、普通恢复和子任务自身恢复的行为均有测试覆盖。

### P2：Windows E2E 默认并发过高导致交互用例偶发超时

问题：高核数 Windows 环境按 CPU 数推导 worker 时会启动过多持久化 Chromium 进程，冲突焦点等交互断言在 4/6 worker 下偶发失败，但目标逻辑在串行或低并发下通过。

修复：Windows 默认 worker 限制为最多 3 个，同时保留 `PLAYWRIGHT_WORKERS` 的显式覆盖能力。该修复只改变测试资源调度，不改变产品运行时行为。

结果：默认配置完整共享 E2E 通过 129/129。

### 追加 UX 批次：任务抽屉与今日空状态

本次按已确认的交互方案完成以下调整：

- 任务抽屉将描述、计划时间、列表直接平铺；标签保留常驻入口，选择器按需展开；重复规则、资料和子任务继续作为低频折叠区。
- 今日页空状态移除重复的“记录第一件事”按钮，只保留顶部快速记录入口，并补充轻量引导文案。
- 开始时间与截止时间保留独立语义字段，但统一为两列网格、控件高度和间距，窄屏自动单列。
- 删除抽屉内的说明性提示；今日任务列表只保留日期上下文，移除不必要的排序规则文案。
- 复核辅助文字对比度：现有 `--muted` 令牌已达到项目记录的 WCAG AA 对比度，不做全局加深，避免破坏既有层级。
- 修复空状态改造后遗留的未定义回调，并让列表补丁恢复相邻焦点时使用 `preventScroll`，避免键盘焦点恢复改变用户视口。

结果：任务抽屉首屏路径更短，今日空状态只有一个主入口，标签与低频设置仍保留键盘路径；390px、键盘展开、自动保存、冲突和列表滚动回归均通过。

## 3. UX、无障碍与安全核验

- Popup 保持固定 380px 宽度，首要输入框可直接记录；Dashboard 与编辑抽屉采用项目设计规范中的线性布局和渐进展开。
- 已确认生产代码不使用浏览器原生 `window.confirm`；破坏性操作使用项目内确认对话框，撤销使用可恢复 Toast。
- 页面根容器没有误用 `aria-live`；动态反馈使用局部 `role=status`/`aria-live`，避免换页时整页播报。
- 任务、子任务、月历、快捷键和表单均保留键盘路径；E2E 覆盖 390px 窄屏、200% 等效视口、焦点恢复和横向溢出。
- 颜色令牌集中在 `src/styles/tokens.css`；状态同时有文字、图标或结构表达，不依赖颜色单独传递信息。
- Manifest V3 仅声明 `storage` 权限，无 host permissions；CSP 为 `script-src 'self'; object-src 'self'`；未发现运行时代码的外部网络依赖。
- `innerHTML` 渲染路径使用转义后的用户文本或固定模板；未发现明显的未转义任务标题、描述或资料内容注入路径。

## 5. 剩余建议

当前级联操作仍采用服务层顺序写入与最佳努力补偿，而不是跨多个任务的一次性 IndexedDB 事务。本轮已用父 revision 预检消除主要的过期父任务风险，现有测试未发现部分状态；若未来需要更强的并发保证，可补充 repository 层 bulk transaction API。

本轮未回滚工作区原有改动，也未删除已有预览配置或截图目录；报告只记录本轮审查与修复结果。

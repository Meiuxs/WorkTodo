# WorkTodo 全项目代码与 UX 审查报告

## 1. 审查结论

审查范围覆盖当前 `src/` 运行时代码、Manifest V3 权限与 CSP、IndexedDB 数据边界、备份导入导出、Dashboard、Popup、响应式布局、键盘与读屏语义、现有单元/E2E 测试以及扩展打包物。

当前没有发现 P0 阻断问题。高风险的数据一致性、跨窗口复制、重复任务撤销、资料关系清理和关键无障碍问题已经修复；完整回归通过后，代码功能层面达到可继续验收状态。

本次由多个独立审查角色并行完成：业务/安全、功能与测试、UX/无障碍/响应式、构建与发布一致性。所有代理均只读审查，最终修改和验证由主工作流完成。

## 2. 发现与处理

### P1：数据一致性与恢复能力

| 问题 | 影响 | 处理结果 |
|---|---|---|
| 资料删除事务未声明 `resourceBlobs`，删除副本时会触发事务错误 | 本地文件副本可能无法删除 | 已修复：补入同一事务 |
| 永久删除任务未清理 `taskResources` | 产生孤儿关系记录 | 已修复：同一事务清理关联 |
| 永久删除父任务未阻止仍有子任务 | 子任务会成为孤儿 | 已修复：仓库层拒绝删除并给出明确提示 |
| 级联完成父任务时父任务冲突会留下已完成子任务 | 状态半完成，撤销困难 | 已修复：失败时按完成顺序补偿恢复，并覆盖重复任务路径 |
| 完成重复任务后撤销只恢复当前任务，未删除新生成实例 | 用户撤销后仍残留下一周期任务 | 已修复：记录 `nextTaskCreated`，撤销时仅删除本次创建且未被复用的实例 |
| 备份 merge 在资源或 metadata 写入失败后没有恢复点 | 可能留下任务已写入、资料未写入的半状态 | 已修复：merge 与 replace 都保存任务、资料副本和 metadata 恢复点 |
| JSON merge 可能覆盖本机已保存文件副本 | 合并备份会使本地副本变成不可下载 | 已修复：合并元数据时保留本机 Blob |

### P1：任务操作与 UX/a11y

| 问题 | 处理结果 |
|---|---|
| 编辑抽屉中“保留为新任务”读取数据库旧值，丢失未保存编辑 | 复制入口现在传递当前表单内容；复制后的 `firstScheduledDate` 与新计划日期一致 |
| 任务、子任务和 Popup 的完成/恢复按钮只有泛化名称 | 可访问名改为“完成任务：任务名”“恢复子任务：子任务名”等，避免同屏同名动作不可区分 |
| 子任务内按 `D/P` 会冒泡到父任务 | 键盘快捷键在子任务区域内显式忽略 |
| 任务编辑、资料表单校验失败后焦点总回到标题 | 按错误类型将焦点移到计划日期、时间、优先级或对应资料字段 |
| 资料错误信息没有和字段建立关系 | 资料表单字段补充错误信息关联；资料选择器失败后聚焦具体字段 |
| 子任务、月历任务完成按钮点击区域过小 | 保留原视觉圆环，扩大可操作命中区域到 44px 级别，并通过 E2E 响应式回归 |
| 今日完成率进度条没有可访问名称 | 增加稳定的 `aria-labelledby` |
| Dashboard 路由、任务列表、编辑抽屉若异步失败可能产生未处理 rejection | 统一在事件入口捕获并交给错误反馈；保留按钮恢复逻辑 |

### P2：数据校验与工程约束

- 备份导入增加重复模板和资料领域级校验，同时兼容早期只保存基础字段的旧模板数据。
- 任务的 `completedAt`、`cancelledAt`、`trashedAt` 增加有效 ISO 时间校验。
- Dashboard 注入当前 Manifest 版本，修复备份导出长期写入 `0.1.0` 的问题。
- `package.json` 与 `package-lock.json` 增加 Node.js 20+ 约束。
- 新增复制内容和首次计划日期的回归测试，并同步扩展仓库事务测试桩以覆盖 `taskResources`。

## 3. 安全与发布检查

- 无 host permissions，无外部网络依赖。
- CSP 为 `script-src 'self'; object-src 'self'`。
